# VO14.1 brief: grants and the audit log

VO14 (capabilities, calendar first) was split at pickup (V1, 2026-11-02) into VO14.1 to VO14.4. This
slice builds the part every capability stands on: a typed list of capabilities, a dated, scoped and
revocable **grant** per assistant, and an append-only **audit log** the person can read. Nothing
reads a calendar yet (VO14.2), and the app gets its screens later (VO14.3), as the ceilings did.

The VO plan's rules this serves (`.ai/DECISIONS.md` and the plan's *Always*): "Every grant is dated,
scoped, revocable and logged where the user can read it." "The broker is the only component that
reads a source, and only a consented one." "A write or send is a capability ask the user confirms."
So there is **no write capability** and no way to grant one: a write will be a confirm per action,
never a standing grant.

## 1. The capabilities

New module `builder/agent/src/grants.rs`, `pub mod grants;` in `lib.rs` (alphabetical, after
`guard`). It sits beside the privacy guard and the spend ledger because a grant is the other half of
the guard: the ceiling says where a source's data may go, the grant says whether Voice may read it
at all.

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub enum Capability { CalendarRead }
impl Capability {
    pub const ALL: [Self; 1] = [Self::CalendarRead];
    pub fn id(self) -> &'static str;            // "calendar.read"
    pub fn source(self) -> Source;              // voice_core::ceilings::Source::Calendar
    pub fn words(self) -> &'static str;         // "read your calendar"
    pub fn from_id(id: &str) -> Option<Self>;   // exact match on id, nothing else
}
```

Every capability is a read. Do not add a kind field or a write variant.

## 2. A grant and its window

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Window { past_days: u16, next_days: u16 }
impl Window {
    pub const DEFAULT: Window = Window { past_days: 0, next_days: 14 };
    pub fn new(past_days: u16, next_days: u16) -> Result<Window>; // past 0..=31, next 1..=92
    pub fn past_days(self) -> u16;
    pub fn next_days(self) -> u16;
}
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Grant { pub capability: Capability, pub given_on: String, pub window: Window }
```

- `Window::new` refuses anything outside the ranges with `Error::Invalid(text::WINDOW_RANGE)`:
  `"The calendar window goes from 0 to 31 days back and from 1 to 92 days ahead."`
- `given_on` is the person's local day, `ledger::local_day(now)` (`YYYY-MM-DD`), as consent is dated.

## 3. Where grants live: `grants.json`

In the assistant's private state folder (`~/.claude/state/<slug>/grants.json`), never in
member.json: a grant belongs to this computer and this person, like `self-hosted.json`.

Exact format, written with `serde_json::to_vec` (compact), grants in `Capability::ALL` order:

```json
{"version":1,"grants":[{"capability":"calendar.read","given_on":"2026-11-02","past_days":0,"next_days":14}]}
```

Reading is strict: `#[serde(deny_unknown_fields)]` on both levels; `version` must be `1`; each
`capability` must be a known id; no capability twice; `given_on` must be `YYYY-MM-DD` (ten
characters, digits and dashes in those places; the month 01 to 12 and the day 01 to 31 are enough);
the window must pass `Window::new`. Anything else, and any read error other than "missing", is
`Error::Invalid(text::grants_damaged(&path))`: `"<path> is damaged, so Voice reads nothing it needs
permission for. Delete it and give permission again."` A damaged file is **never** read as "no
grants" by any function here. Read with `read_private_optional_at_max(home, slug, None,
"grants.json", 64 * 1024)`.

Functions (all `pub` in `grants`, `now: SystemTime` passed in so tests can fix the clock):

- `load(home, slug) -> Result<Vec<Grant>>`: missing file (or missing state folder) is an empty list.
- `give(home, slug, capability, window, now) -> Result<Grant>`: the caller holds the state lock.
  Loads (a damaged file is the error, nothing written), replaces any grant for that capability,
  writes with `write_private`, then appends the `grant` audit line (§ 4). **If the append fails, put
  the previous `grants.json` back** (its old bytes with `write_private`, or `remove_private` when
  there was none) and return the append's error: a grant nobody can see in the log must not stand.
- `revoke(home, slug, capability, now) -> Result<bool>`: the caller holds the state lock. `false`,
  with nothing written and nothing logged, when there was no grant for it. Otherwise writes the file
  without it (remove the file when no grant is left), then appends the `revoke` line; if the append
  fails, put the old file back and return the error.
- `require(home, slug, capability, step, now) -> Result<Grant>`: for VO14.2's reader. Returns the
  grant when there is one. With none it appends a `refused` line with reason `no-grant` and returns
  `Error::Invalid(text::no_grant(capability))`:
  `"Voice doesn't have your permission to read your calendar for this assistant."` (built from
  `capability.words()`: `"Voice doesn't have your permission to {words} for this assistant."`).
  With a damaged file it appends a `refused` line with reason `damaged` and returns the damaged
  error. If that append itself fails, return the append's error (refusal either way).
- `record_read(home, slug, capability, step, items: u64, now) -> Result<()>`: appends a `read`
  line. VO14.2 calls it after each read.

`step` is the name of the Voice step asking (`"cli"` in tests; VO14.2 and VO14.4 add theirs). It
must be 1 to 32 characters of `a-z`, `0-9` and `-`, starting with a letter; anything else is
`Error::Invalid` and nothing is written.

## 4. The audit log: `audit.jsonl`

In the same state folder. One compact JSON object per line, appended with `append_private`
(0600, never follows a link, owner-only, `flock`ed). Fields in exactly this order, `at` from
`ledger::utc_stamp(now)`:

```json
{"at":"2026-11-02T12:00:00Z","event":"grant","capability":"calendar.read","past_days":0,"next_days":14}
{"at":"2026-11-02T12:00:00Z","event":"revoke","capability":"calendar.read"}
{"at":"2026-11-02T12:00:00Z","event":"read","capability":"calendar.read","step":"cli","items":12}
{"at":"2026-11-02T12:00:00Z","event":"refused","capability":"calendar.read","step":"cli","reason":"no-grant"}
```

Never a path, a title, a name, an error's text or any content: only these fields. Reasons are the
fixed ids `no-grant` and `damaged`.

Reading it back: `audit(home, slug, last: usize) -> Result<Audit>` with

```rust
pub struct Audit { pub entries: Vec<Entry>, pub unreadable: usize, pub older: bool }
pub struct Entry { pub at: String, pub event: Event }
pub enum Event {
    Grant { capability: Capability, window: Window },
    Revoke { capability: Capability },
    Read { capability: Capability, step: String, items: u64 },
    Refused { capability: Capability, step: String, reason: Reason },
}
pub enum Reason { NoGrant, Damaged }
```

- `last` must be 1 to 1,000 (`Error::Invalid(text::AUDIT_LAST)`: `"Show between 1 and 1,000
  entries."`). Entries come newest first.
- Read at most the file's **last 1 MiB**. Add to `builder/ingest/src/private.rs`
  `pub fn read_private_tail_optional(home, slug, name, max: u64) -> Result<Option<(Vec<u8>, bool)>>`:
  the same checks as `read_private_optional_at_limit` (no state folder or no file is `Ok(None)`; the
  name validated; opened by the folder's descriptor with `O_NOFOLLOW`; a regular file; owner-only,
  as `only_mine` checks) but, instead of refusing a larger file, it reads only its last `max`
  bytes and returns `true` when it skipped any. Share the opening code with
  `read_private_at_limit` rather than copying it.
- When bytes were skipped, drop everything up to and including the first `\n` (a cut line is not
  counted as unreadable) and set `older = true`. `older` is also `true` when more complete entries
  were read than `last`.
- A line that isn't exactly one of the four shapes (strict: unknown fields, unknown ids, a bad
  window, a step that fails § 3's rule, `at` not `YYYY-MM-DDTHH:MM:SSZ`) counts in `unreadable`
  and is never shown. An empty trailing line is not a line. A missing file is an empty `Audit`.

## 5. The CLI

In `builder/cli/src/main.rs`, two command groups beside `self-hosted`, same style (doc comments are
the help text):

```
voice grants show <member_dir>
voice grants give <member_dir> <capability> [--past-days N] [--next-days N]
voice grants revoke <member_dir> <capability>
voice audit show <member_dir> [--last N]
```

- `--past-days` defaults to 0, `--next-days` to 14; `--last` to 50. clap parses numbers as `u16` /
  `usize`; the range checks are §§ 2 and 4's, with their sentences.
- An unknown capability: `Error::Invalid(text::unknown_capability(id))`: `"<id> isn't something Voice
  can be given permission for. It can be given: calendar.read."` (the list from `Capability::ALL`).
- `give` and `revoke` take the state lock with `lock_existing_state`; when the state folder doesn't
  exist yet the error is `text::NO_STATE_FOR_GRANTS`: `"This assistant has no private state yet.
  Build it once, then give permission."` `show` and `audit show` take no lock and create nothing.
- Output, exactly (`<name>` is the member's `name`; `{window}` below):
  - `show`, one line per capability in `ALL` order: `calendar.read\ton\tread your calendar,
    {window}, given 2026-11-02` or `calendar.read\toff\tread your calendar`.
  - `give`: `Voice may now read your calendar for <name>, {window}.`
  - `revoke`: `Voice may no longer read your calendar for <name>.`, or when there was no grant:
    `Voice didn't have permission to read your calendar for <name>, so nothing changed.`
  - `audit show`: one line per entry, newest first: `<at with the T as a space and the seconds and
    Z dropped> UTC  <what>`, e.g. `2026-11-02 12:00 UTC  given: read your calendar, from today to
    14 days ahead`. `<what>` is `given: <words>, {window}`, `taken back: <words>`, `read: <words>,
    <items> items, for <step>` (`1 item` for one), `refused: <words>, for <step>, no permission`
    or `refused: <words>, for <step>, the permissions file is damaged`. Then, when
    `unreadable > 0`: `<n> entries couldn't be read.` (`1 entry couldn't be read.`); when
    `older`: `Older entries aren't shown.`; when there are no entries and neither line applies:
    `Nothing has been logged for <name> yet.`
  - `{window}`: past part `from today` (0) or `from 1 day back` / `from <n> days back`; then
    ` to 1 day ahead` / ` to <n> days ahead`.
- Every sentence lives in `builder/agent/src/text.rs` beside the self-hosted ones.
