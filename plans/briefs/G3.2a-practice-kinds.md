# G3.2a brief: draft practice questions on kinds of decision you name

`voice interview draft` picks its own kinds of decision. A full interview covers every kind; a short one
covers the kinds an earlier build's report or labels show as thin (`interview::thin_kinds`, fewer than 5
examples). A helper that already knows where an assistant is weak (for example, from the calibration
table in its `decisions.md`, which marks the kinds that fell just short of *live*) has no way to say "ask
about these kinds". It also has no way to keep that practice round apart from the person's own interview.
This slice adds that, and nothing else: `--kind` (repeatable) and `--per-kind`. The answers to a practice
round are kept with `voice keep`, one answer at a time, by whoever asked. `interview answer` never sees a
practice round.

Read first: `AGENTS.md`, `.ai/PROJECT.md`, `CONTRIBUTING.md`, `builder/build/src/interview.rs` (all of
it: `Form`, `thin_kinds`, `prompt`, `check`, `draft`), `builder/build/src/text.rs` (the interview words:
`ALREADY_DRAFTED`, `NOTHING_TO_ASK`, `drafted`, `drafted_short`, `swap`), `builder/cli/src/main.rs`
(`InterviewCommand::Draft`, `DraftArgs`, `DraftPlan`, `draft_plan`, `interview_draft`, `interview_answer`),
`builder/api/src/building.rs` (its `interview::` calls; they stay as they are), and the tests
`builder/cli/tests/interview.rs` and `builder/build/tests/interview.rs`.
Skills: `~/.codex/skills/tdd-skill/SKILL.md`, `~/.codex/skills/code-quality/SKILL.md`,
`~/.codex/skills/plain-language/SKILL.md`, `~/.codex/skills/security-and-hardening/SKILL.md`.

## 1. Decisions already made (do not change them)

- **The flags**, on `voice interview draft` only:
  - `--kind <KIND>`, repeatable (`Vec<String>`). Help text: `Draft a practice round on this kind of
    decision only; repeat for up to 5 kinds. Keep each answer with voice keep.`
  - `--per-kind <N>`: an integer from 1 to 4 (clap `value_parser!(u8).range(1..=4)` or the `usize`
    equivalent), default 4, and `requires = "kind"`. Help text: `With --kind: how many questions on each
    kind, 1 to 4 (default 4).` A value outside 1 to 4, or `--per-kind` without `--kind`, is clap's usage
    error (exit 2). That is fine.
- **Checking the kinds.** Check them first, in `draft_plan` (it already runs before any lock, ledger or
  call). Check each named kind in the order given:
  - Each must be one of `book.categories` and must not be `other`. Otherwise:
    `{kind:?} isn't one of the kinds of decision in your assistant's settings (other doesn't count).`
    Use `{kind:?}` (Rust's `Debug`) so a control character in an argument is printed escaped.
  - No kind may be named twice: `{kind:?} is named twice.`
  - At most 5 kinds (`interview::MOST_THIN_KINDS`): `Name at most 5 kinds of decision.`
  Each check is an `Error::Invalid`, so it exits 1. Put the three sentences in `voice_build::text`
  (two `fn`s and one `const`). A refused flag makes no model call and writes nothing to the private
  folder: no questions file, no `runs.jsonl` line.
- **The form.** A new variant, `Form::Practice { per_kind: usize }`. With `--kind`, the form is always
  `Practice`, whatever the corpus holds (so `Form::for_answered` is not consulted, and the corpus and
  `--labels` are ignored for the form and the weights). The weights are the named kinds in the order
  given, each with `None` for its count. For `Practice`:
  - `step()` is `"interview-practice"` (the ledger's step name);
  - `questions_file()` is `"interview-practice-questions.json"`;
  - `count(weights)` is `per_kind * weights.len()`;
  - `answers_file()` and `out()` are `"interview-practice-answers.json"` and
    `"decisions-interview-practice.jsonl"`. Nothing reads or writes them in this slice. They exist only
    because those methods return a name for every form; add one doc line on the variant saying a
    practice round's answers go to `voice keep`.
  `Form::for_answered` still returns only `Full` or `Short`, so `interview answer` and the app never
  reach `Practice`. Do not change `interview_answer` or `builder/api`.
- **The prompt.** `prompt(Form::Practice { .. }, book, weights)` follows the `Short` branch's shape. Two
  changes: the kinds line reads `The kinds of decision to ask about (the ones to practise):`, and the
  spread rule reads `Exactly {per_kind} question on each kind of decision listed above.` when
  `per_kind == 1`, and `Exactly {per_kind} questions on each kind of decision listed above.`
  otherwise. Every other line is the same text the other forms get, including the total count line
  and the rule against naming a real person or asking about private matters.
- **The check.** `check(Form::Practice { .. }, …)` is the same as for `Short`: exactly `count`
  questions, numbered 1 to count, each header one of the named kinds, every named kind covered. Since
  `count` is `per_kind × kinds`, a draft that covers every kind with exactly `count` questions passes.
  A draft that puts two questions on one kind and none on another fails the coverage rule. Each kind
  having exactly `per_kind` questions is **not** checked beyond that, as for `Short`. Do not add a check.
- **Already drafted.** The `ALREADY_DRAFTED` check (both the first look and the second, under the
  lock) runs against `interview-practice-questions.json` for a practice round. `--replace` replaces
  that file only. A practice round never reads, writes or replaces `interview-questions.json` or
  `interview-short-questions.json`, and a waiting short or full draft never blocks a practice round.
- **What it prints** after a practice draft, in this order:
  1. `Drafted {count} practice questions on: {kinds joined by ", "}.` (new `text::drafted_practice`);
  2. `saved to ~/.claude/state/{slug}/interview-practice-questions.json` (the existing line);
  3. `Keep each answer as a test for your assistant: voice keep {folder} --signal <a file in its private
     folder>` (new `text::practice_next(folder)`, used in place of `text::swap`);
  4. the closing spend line, as today.
  Full and short drafts print exactly what they print today.
- **No other change.** No change to the app, the API types, `parity.rs`, `interview answer`, `keep`, or
  the full or short rounds. If `builder/cli/tests/app_parity.rs` (or any parity test) fails because the
  CLI gained a flag the app lacks, stop and report. Do not add an app field.

## 3. Tests to write first (dispatch A)

All in `builder/cli/tests/interview.rs`, on Wren (the template's kinds are `scope`, `sequencing`,
`methods`, `framing`, `writing-voice`, `communication`, `collaboration`, `compliance-ethics`,
`tooling`, `verification`, `placement-naming`, `go-no-go`, `other`). Add a helper that builds a
practice draft: `n` from 1, a given header per question, two options, `recommended: null`.

1. **A practice round on two kinds.** `f.signed_in(ok_reply(practice draft: headers [methods, framing]))`,
   with `f.write_state("decisions.jsonl", &corpus(2))` so a full interview would otherwise be chosen.
   `interview draft <member> --kind methods --kind framing --per-kind 1` exits 0, with exactly 1 call.
   `interview-practice-questions.json` holds 2 questions with headers `methods` then `framing`.
   Neither `interview-questions.json` nor `interview-short-questions.json` exists. Stdout starts with
   `Drafted 2 practice questions on: methods, framing.\nsaved to ~/.claude/state/wren/interview-practice-questions.json\nKeep each answer as a test for your assistant: voice keep `
   (then the member path). Every `runs.jsonl` line has `step` `interview-practice`.
2. **The prompt names only the named kinds.** In test 1's `stdin`: it contains
   `The kinds of decision to ask about (the ones to practise):`, the lines `- methods\n` and
   `- framing\n`, and `Exactly 1 question on each kind of decision listed above.` It contains no
   `- scope\n` and no `- sequencing\n`.
3. **Four per kind by default.** `--kind tooling` with a stub reply of 4 tooling questions exits 0, and
   the saved file holds 4. The prompt holds `Exactly 4 questions on each kind`.
4. **Refusals make no call and write nothing.** Each case exits non-zero, `f.calls() == 0`, and
   `interview-practice-questions.json` and `runs.jsonl` don't exist:
   - `--kind other` and `--kind nope`: stderr holds `"other" isn't one of the kinds of decision` or
     `"nope" isn't …`;
   - `--kind scope --kind scope`: `"scope" is named twice.`;
   - six distinct valid kinds: `Name at most 5 kinds of decision.`;
   - `--per-kind 0`, `--per-kind 5`, and `--per-kind 2` without `--kind`: exit code 2.
5. **A draft that misses a kind is asked for again, then refused.** A stub reply whose 2 questions are
   both `methods`, for `--kind methods --kind framing --per-kind 1`: exits non-zero, 2 calls, no
   practice file.
6. **Kept apart from the person's own interview.** With `interview-short-questions.json` already
   written (use the existing `short_draft()`), a practice draft still succeeds and leaves that file
   byte-for-byte unchanged. Then a second practice draft without `--replace` fails with
   `ALREADY_DRAFTED`'s sentence and makes no new call. With `--replace` it succeeds and replaces only
   the practice file.
7. **Without `--kind`, nothing changes.** The existing tests stay as they are and pass. Do not edit
   them.

**Dispatch A writes only these tests and the helper.** Change no other file. The tests are expected to
fail; do not make them pass. Run `cargo test -j 2 -p voice-cli --test interview`, and report each new test's
