# G3.1a brief: an approval or a rejection can carry the approver's note

The growth loop spec lets an approval carry a `note`, "anything the approver added"
(`docs/spec/growth-loop.md` § *4. Approval*, `approval.schema.json`), and `voice_grow::record::Approval`
already has the field (`builder/grow/src/record.rs`, `note: Option<String>`, refused when empty). But
nothing can set it: `refresh::answer_locked` always saves `note: None` (`builder/grow/src/refresh.rs`),
and `voice refresh approve` and `reject` take only the assistant's folder and the change's id. A person
who answers a change somewhere else (for example in a message, which a scheduled helper then turns into
`voice refresh approve`) has no way to keep their words with the answer. This slice adds that, and
nothing else.

Read first: `AGENTS.md`, `.ai/PROJECT.md`, `CONTRIBUTING.md`, `docs/spec/growth-loop.md` (§ *Who
approves*, *Rules*, *4. Approval*), `builder/grow/src/refresh.rs` (`answer`, `answer_locked`),
`builder/grow/src/record.rs` (`Approval`, its `check`), `builder/grow/src/text.rs`,
`builder/cli/src/main.rs` (`RefreshCommand::Approve` and `Reject`, `refresh_answer`, and `keep_answer`
for how a file inside the assistant's private folder is read), `builder/ingest/src/private.rs` (`place`,
`validate_json_name`, `read_private_at_max`), `builder/api/src/review.rs` (its `answer_locked` call),
and their tests: `builder/grow/tests/refresh.rs`, `builder/cli/tests/refresh.rs`,
`builder/cli/tests/keep.rs`, `builder/cli/tests/app_parity.rs`.

## 1. Decisions already made (do not change them)

- **The flag.** `voice refresh approve <MEMBER_DIR> <CHANGE> [--note <FILE>]` and
  `voice refresh reject <MEMBER_DIR> <CHANGE> [--note <FILE>]`. Help text for the flag:
  `Your words to keep with your answer: a JSON file in your assistant's private folder, NAME or
  FOLDER/NAME, holding {"note": "..."}`.
- **Where the file is.** Exactly as `voice keep` reads its signal: `voice_ingest::private::place`, then
  `validate_json_name`, then `read_private_at_max(home, slug, folder, name, 16 * 1024)`, under the same
  history lock `keep_answer` takes (`history_lock_existing`). That lock is the same state lock
  `Store::lock` takes inside `refresh::answer`, so when `--note` is given, `refresh_answer` takes
  `history_lock_existing` once, reads and checks the note, then calls `refresh::answer_locked` (never
  `refresh::answer`, which would take the lock a second time and fail as busy). Without `--note`, keep
  today's path through `refresh::answer` unchanged. So the note is only ever read from inside
  `~/.claude/state/<slug>/`, as a plain `.json` name, with the private folder's own checks (owner,
  mode, no symlink). Never a path of its own. Reuse those functions; write no new file reader.
- **The file's shape.** A JSON object with exactly one key, `note`, a string
  (`#[serde(deny_unknown_fields)]`). Anything else (not JSON, another key, a missing key, a non-string)
  is refused with `The note file must hold {"note": "..."} and nothing else.` and exit 1.
- **The note's text.** Trimmed of leading and trailing whitespace. Refused when, after trimming, it is
  empty (`The note is empty.`), or holds a control character other than newline and tab
  (`The note can't hold control characters.`). Keep it otherwise exactly as written, newlines included.
  Put these three sentences in `voice_grow::text` beside the other refresh words.
- **Order.** The note is read and checked **before** `refresh::answer` runs, so a refused note leaves no
  approval or rejection on file and the change stays open. Assert that in a test.
- **The record.** `refresh::answer` and `refresh::answer_locked` gain a `note: Option<&str>` parameter
  (after `decision`, before `now`), saved as the `Approval`'s `note`. `None` keeps today's behaviour:
  the field is omitted from the saved JSON (it already is: `skip_serializing_if`). Update every caller:
  the CLI, `builder/api/src/review.rs` (passes `None`; the app gets no note field in this slice), and
  the grow tests.
- **What it prints.** The same line as today (`text::approved` / `text::rejected`), unchanged. Never echo
  the note.
- **No other change.** `refresh show`, `apply`, `propose`, the app's screens and API types are unchanged.
  If `builder/cli/tests/app_parity.rs` requires every CLI flag to exist in the app, stop and report
  instead of adding an app field.

## 3. Tests to write first (they must fail before the change, on their assertion)

In `builder/cli/tests/refresh.rs`, after a `refresh propose` as the existing tests do:

1. `approve --note notes/a.json` (written with `write_state` into a `notes` folder inside the
   state folder, 0700, the file 0600; at least one other test uses a top-level `NAME`) holding `{"note": "  Yes, try it.\nKeep the old rule too.  "}` succeeds, prints exactly the
   usual approved line, and the one `appr-` record has `note` equal to
   `"Yes, try it.\nKeep the old rule too."` and `decision` `approved`.
2. The same for `reject --note`: `decision` `rejected`, the note saved.
3. Without `--note`, the saved approval has no `note` key at all (`approvals[0].get("note").is_none()`).
4. Refusals, each exit non-zero with its sentence on stderr, **no `appr-` record written**, and a later
   plain `approve` of the same change still succeeds: an empty note (`"   "`), a control character
   (`"a\u0007b"`), a wrong shape (`{"note": 1}`, `{"note": "x", "by": "y"}`, `not json`), a name that
   isn't `.json`, a path with two folders (`a/b/c.json`), and a missing file.
5. A note file over 16 KiB is refused, with no record written.

In `builder/grow/tests/refresh.rs`: `answer(..., Some("ok"), NOW)` saves `note: Some("ok")`; `None`
saves `None`.
