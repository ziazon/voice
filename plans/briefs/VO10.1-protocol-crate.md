# VO10.1 brief: the panel protocol as a Rust crate

Panels let several AI assistants work one question out in rounds and come back with a joint
proposal, plus the dissent of any who would not agree. The rules that run a panel (how a post's
last block is read, how far apart the members are, when one is a holdout, when the panel has
agreed or is stuck, how the result is written) exist today as a small pure-Python reference
protocol with 66 portable JSON test vectors. This slice ports that protocol to a new Rust crate,
`builder/panels` (package `voice-panels`, library `voice_panels`), with **no I/O at all**: no
files, no processes, no network, no clock. The runner that calls models and the screen come in
later slices. Another app may depend on this crate, so its JSON shapes (the state, the round
report, the result) are a contract: they must read and write exactly what the reference does.

## Rust-specific rules (where a straight port would drift from the reference)

1. **Members in order.** Every loop over members iterates `crew` (or `names`) in its given order,
   never a map's order: combinations for the matrix and the group mean, group search, dissent,
   the list answer. Maps are only lookups.
2. **Lengths are characters.** `len()` in the reference counts code points: use
   `chars().count()`, and truncate with `chars().take(max)` before appending `…`.
3. **`clean`.** Replace with a space each character where `char::is_control()` is true (exactly
   Unicode category Cc) other than `\n` and `\t`, and each of U+200B–U+200F, U+2028–U+202E,
   U+2060–U+2069 and U+FEFF; then `trim()`; then truncate. After that replacement Rust's
   `trim()` and `split_whitespace()` match Python's `strip()` and `split()`.
4. **`match_key` casefolds.** Python's `casefold()` is full Unicode case folding (`ẞ` → `ss`,
   `ﬁ` → `fi`, `ς` → `σ`, Cherokee small letters → capitals), which `to_lowercase()` is not.
   `gen_casefold.py` prints `src/casefold_table.rs`: every code point `c` (0 to 0x10FFFF, minus
   surrogates) where `chr(c).casefold() != chr(c).lower()`, sorted, as `('\u{XXXX}', "…")` with
   the string escaped for Rust (`\u{…}` for anything outside printable ASCII); the file's header
   comment names the Python and Unicode versions (`sys.version_info`, `unicodedata.unidata_version`)
   and says it is generated by `python3 builder/panels/gen_casefold.py > builder/panels/src/casefold_table.rs`.
   Run it with the `python3` on `PATH` and commit its output. `casefold(s)` maps each character
   through the table (binary search), else through `char::to_lowercase()`. Never call
   `str::to_lowercase()` (it applies the final-sigma rule, which casefold does not).
   `match_key(item) = casefold(split_whitespace(clean(item, 10_000)).join(" "))`.
5. **Regexes** compile once (`std::sync::LazyLock<Regex>`): email
   `[\w.+-]+@[\w-]+(\.[\w-]+)+`, path `(?:^|[\s(\["'`=])(?:~/|/)[\w.-]+/`, and per term
   `(?i)\b<regex::escape(term)>\b`, skipping empty terms. If a term's regex fails to build, count
   it as a `term` finding (a guard that cannot check withholds).
6. **The last block** (`_last_body`). Split the post on `\n` only. For matching a fence line, drop
   one trailing `\r`; the body lines returned keep theirs. An opening line is three or more
   backticks, then `deliberation`, then only spaces (not tabs); a closing line is at least as many
   backticks as its opening, then only spaces. Only complete fences count; the last complete one
   wins, and a malformed last complete body never falls back to an earlier one. Write it without a
   regex (count backticks, compare the rest).
7. **A field line** (`_fields`). Skip lines that are empty after trimming. Split at the first `:`;
   no colon, a key outside the six, or a repeated key makes the block malformed. Trim key and
   value.
   - A value starting with `"`, `[` or `{` is JSON. Before parsing, rewrite each raw character
     U+0000–U+001F that sits **inside a JSON string** as `\u00XX` (walk the value tracking "inside a
     string" and backslash escapes), so a literal tab parses as `strict=False` allows. Parse the
     first value with `serde_json::Deserializer::from_str(..).into_iter::<Value>()` and take
     `byte_offset()`; what follows, trimmed, must be empty or start with `#`. A parse error makes
     the block malformed. Duplicate keys inside an object: the last one wins (serde_json does
     this).
   - Any other value: cut at the first ` #`, trim, then try `serde_json::from_str::<Value>`. If it
     parses, use that value. If the text is exactly `NaN`, `Infinity` or `-Infinity` (which
     Python's `json.loads` accepts as floats), use `Value::Null`: every place a field is read
     rejects both a float and a null, so the verdict is the same. Otherwise keep the text as a
     string.
8. **Numbers.** "An int" (the reference's `type(x) is int`) is a JSON number for which `as_i64()`
   is `Some`, and never a boolean. `7.0` and `1e2` are floats and so are refused as ratings.
   Python reads `-0` as the int 0 but `-0.0` as a float; serde_json reads both as `-0.0` (checked),
   so the text decides: in the same walk that escapes control characters (rule 7), rewrite a number
   token outside any string that is exactly `-0` (the next character is not a digit, `.`, `e` or
   `E`) to `0`.
9. **Draft ids.** `<author>.r<round_no>`. In the text answer's tie-break, the round is the text
   after the last `.r`, parsed as `i64` after trimming; anything else is
   `ProtocolError::BadDraftId`.
10. **Float comparisons** keep the reference's epsilons exactly (`1e-12` for progress, holdout
    falls and the `1/3` group link) and use `f64::total_cmp` for sorting.
11. **State JSON.** `to_json` is `serde_json::to_value(self)`. `from_json` deserializes, then
    validates as `new` does (kind and n, 2 to 24 unique non-empty names) and fills any member
    missing from `last_block`, `weight`, `holdout`, `stall` or `prev_own` with `None`, `1.0`,
    `false`, `0` and `1.0`, as the reference's `__post_init__` does. A JSON error or a failed check
    is `ProtocolError::InvalidState`.
12. **The markdown** is the reference's `render_markdown` to the byte. `_answer_text` writes `None`
    for no answer, a list as `"[" + items.map(serde_json::to_string).join(", ") + "]"` (Python's
    `json.dumps` separators; serde_json's string escaping matches `ensure_ascii=False`), and text
    as is. The `D:` line is `"[" + d.map(py_float_repr).join(", ") + "]"`, where the private
    `py_float_repr` reproduces Python's `repr(float)`: take the shortest digits and exponent from
    `format!("{:e}", x.abs())`; zero is `0.0` (or `-0.0`); use plain notation when the decimal
    exponent `e` satisfies `-4 <= e < 16` (always with at least one digit after the point, `1.0`),
    otherwise `d[.ddd]e±XX` with a sign and at least two exponent digits (`1e-05`, `1e+16`).
    Group weights use `{:.2}`.
13. **The time box.** `timebox_decision` takes a typed `Option<TimeBox>`, so the reference's
    "unknown time box" error lives in `TimeBox::parse`. `mean` is the plain arithmetic mean.
14. **No panics** on any input to `parse_block`, `clean`, `match_key`, `leak_findings`, `fence`,
    `evaluate_fixture` or `DeliberationState::from_json`: no `unwrap`, `expect`, indexing that can
    go out of bounds, or byte slicing off a character boundary on a path that input reaches.
    Errors are values.

`replay.rs` ports `replay.py`: a `parse` vector maps `kind` through `Kind::parse` (an unknown kind
is a malformed block, as in the reference), builds `known_drafts` from the list and answers
`{"malformed": true}` or `{"block": <Block as JSON>}`; a `timebox` vector answers the decision as
JSON; a `rounds` vector builds the state, steps each round (a `null` entry is no block; the block
is built from the vector's fields with `draft_id` set when `draft` is present), calls `reopen`
after the round numbered `reopen_after`, and answers
`{"rounds": [<each report as JSON without "agreed_answer">], "result": <build_result as JSON>}`.
No rounds, an unknown `type` or a field of the wrong shape is `ProtocolError::Fixture`.

## Dispatch E: Python's compensated sum

A differential run (random panels through both the reference and this crate) matched to the
byte once the reference's built-in `sum` was swapped for a plain left-to-right sum, and differed
only in the markdown's `D:` line otherwise: since Python 3.12, `sum()` over floats uses Neumaier
compensated summation (checked: Python 3.12 gives `sum([0.1] * 10) == 1.0`, Python 3.9 gives
`0.9999999999999999`). The crate follows Python 3.12 and later. `reference_probes.json` now has a
`rounds` list: twelve panels (`fixture`, the full `result`, its `markdown`) where the two sums
differ.
