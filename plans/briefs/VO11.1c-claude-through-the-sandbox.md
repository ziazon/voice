# VO11.1c brief: every `claude` through the sandbox

VO11.1a landed the egress proxy (`builder/agent/src/egress.rs`, `Egress`), VO11.1b the sandboxed
launch as a library (`builder/agent/src/sandbox.rs`, `Launch`), and VO11.1d the proxy's
should-fixes. Both are unwired. This slice wires them: every `claude` Voice starts (the check's two
runs, each call, the sign-in) goes through one `Launch` with one `Egress` of its own. After it,
nothing of the person's environment reaches Claude Code, so `ANTHROPIC_API_KEY` can no longer reach
it and the API-key note goes.

Read first: `AGENTS.md`, `.ai/SECURITY.md`, `CONTRIBUTING.md`, `docs/spikes/VO11-os-sandbox.md`,
`plans/briefs/VO11.1b-sandboxed-launch.md` (§ *What V1 measured* and § 2), then in full:
`builder/agent/src/claude.rs`, `sandbox.rs`, `child.rs`, `egress.rs` (its public surface: `start`,
`port`, `stop`, `Drop`), `ledger.rs` (`open_at`, `work_folder`), `text.rs`,
`builder/agent/tests/common/mod.rs`, `builder/api/src/assistants.rs` (`ready_status`,
`claude_check_in`, `claude_sign_in_in`, `claude_message`) and `builder/cli/src/main.rs`
(`claude_check`, `claude_sign_in`). Skills: `~/.codex/skills/tdd-skill/SKILL.md`,
`~/.codex/skills/security-and-hardening/SKILL.md`, `~/.codex/skills/code-quality/SKILL.md`,
`~/.codex/skills/plain-language/SKILL.md` (the one new sentence).

Public repo: invented names only, no fixed paths, no real person. **Add no dependency** to any
crate's `[dependencies]` (`libc` is already one of `voice-agent`'s). Match the surrounding code:
comment density, naming, test style. Commit nothing; leave every change in the working tree.

**Your sandbox can't bind loopback sockets or nest `sandbox-exec`.** After this slice every
`claude` launch starts an `Egress` (a loopback bind), so every stub test fails at the bind for you.
Write the tests, run what you can (`cargo build --all-targets`, `cargo clippy --all-targets --
-D warnings`, `cargo fmt --check`, and `cargo test` for crates that start no `claude`), and report
which tests you could not run. V1 runs the rest outside your sandbox. Never weaken an assertion to
make a test pass for you.

## What V1 measured on Mimi, 2026-11-02, Claude Code 2.1.292 (don't re-derive it)

A sandboxed, signed-out `claude -p` (the VO11.1b profile, environment from nothing,
`CLAUDE_CODE_TMPDIR` = the run folder) **leaves a `claude-<uid>/` folder in its run folder**. So the
session's work folder can't be the run folder: `Session::work_folder` refuses a non-empty folder,
and the second call would fail. **Every launch uses `RunFolder::Fresh`** (a new 0700 folder in
`runs/` beside the profile, removed when the `Launch` drops), which is also empty and Voice-owned,
the work folder's only purpose. `RunFolder::Given` stays in `sandbox.rs` (it is VO11.1b's tested
library surface) but Voice no longer passes it.

## 1. The test-only bypass: feature `test-stubs` on `voice-agent`

Stub `claude`s in the tests are `#!` scripts. A script can't run inside the sandbox
(`resolve_program` refuses it with `text::NOT_NATIVE`), so tests need a way past `sandbox-exec`
that production builds never have.

1. `builder/agent/Cargo.toml`: `[features] test-stubs = []` (no default features). Doc comment
   above it: *test builds only: a `#!` script runs directly instead of inside the sandbox;
   `scripts/ci-local.sh` checks the app and CLI builds lack it.*
2. Enable it **only from `[dev-dependencies]`**: in `builder/agent/Cargo.toml` itself
   (`voice-agent = { path = ".", features = ["test-stubs"] }`; Cargo accepts a crate naming itself
   there, V1 checked), and in each crate whose tests start a stub `claude`: `voice-api`,
   `voice-build`, `voice-cli`, `voice-grow`, `voice-panel-runner` (a dev-dependency entry
   `voice-agent = { path = "../agent", features = ["test-stubs"] }` beside the normal one). If one
   of those crates' tests turns out not to start a `claude`, leave its manifest alone and say so.
3. `sandbox.rs`, in `Launch` (macOS `new` only; the non-macOS `new` still refuses with
   `text::MAC_ONLY`, feature or not):
   - New private field `direct: bool`.
   - In `Launch::new`, where it now calls `resolve_program(program)`: under
     `#[cfg(feature = "test-stubs")]`, first canonicalise the program, require a regular file with
     an execute bit, and read its first two bytes; when they are `#!`, the launch is `direct` and
     the canonical path is the program. Otherwise (and always without the feature) call
     `resolve_program` exactly as today. `resolve_program` itself does not change, so it still
     refuses scripts in every build (its existing test keeps passing with the feature on).
   - Everything else in `new` is unchanged for a direct launch: the profile checks, the run
     folder, the sign-in helper.
   - In `Launch::command`: when `direct`, the command is `Command::new(&self.program)` followed by
     the same `--setting-sources project,local`, the same `args`, the same `current_dir`, and the
     same environment, built by the same code (factor the environment into one private method both
     branches call, so the two can't drift). When not `direct`, exactly today's `sandbox-exec`
     command.
   - Write the field and the branch so the non-feature build has no unused field, variable or
     import warning (for example, `direct` set to `false` outside the `cfg` block and the field
     present in both builds is fine; a `#[cfg]` on the field is also fine). § 6 makes ci-local
     build the non-feature configuration with `-D warnings`.

## 2. `builder/agent/src/claude.rs`

### 2.1 The profile is required

- `Claude.profile: PathBuf` (no longer `Option`). `Claude::at(program: PathBuf, profile: PathBuf)`;
  it makes no folder (a launch checks the profile is a private folder and fails with
  `text::PROFILE_FAILED` when it is not). `find_in` builds it with the folder `ensure_profile`
  made, as today. `profile(&self) -> &Path`.
- Update every `Claude::at` caller (only tests call it: the agent, build, cli and grow crates'
  tests; `git grep -n 'Claude::at'`) to pass a profile folder they create with mode 0700, for
  example `<their scratch>/profile`. In `builder/agent/tests/common/mod.rs`, `Stub::claude()` makes
  `<stub folder>/profile` (0700, created once, reused) and passes it; add
  `Stub::profile(&self) -> PathBuf` for assertions.

### 2.2 One launch: `fn launch(&self, home: &Path, sign_in: bool) -> Result<(Egress, Launch)>`

Private. In this order:
1. `Egress::start()`; any error becomes `Error::Invalid(text::PROXY_FAILED)` (§ 4).
2. `Launch::new(&self.program, &self.profile, home, RunFolder::Fresh, egress.port(), sign_in)`;
   its error is returned as it is (`NOT_NATIVE`, `DOES_NOT_RUN`, `PROFILE_FAILED`,
   `RUN_FOLDER_FAILED`, `MAC_ONLY` keep their own text). The egress is dropped (and so stopped) on
   that path.
3. Return both. Every caller keeps both alive until `child::run` has returned, then drops the
   `Launch` (removing the run folder) and calls `egress.stop()`.

`home` is only `Launch`'s `HOME`; the child never runs in it.

### 2.3 What goes

- `fn command`, `SESSION_MARKERS`, `fn provider_override` and their comments: the launch's
  environment is built from nothing, so there is nothing left to remove.
- `pub fn sign_in_command`: the CLI now calls `sign_in` (§ 3.2).
- `Ready.api_key_set`, `Status.api_key_set`, the `ANTHROPIC_API_KEY` read in `status`, and their
  doc comments. `Ready { version }`, `Status { version, signed_in }`.
- `session.work_folder()` in `call` (§ *What V1 measured*). In `ledger.rs`: `Session::work_folder`,
  `WORK_FOLDER`, and the `private_folder(home, slug, WORK_FOLDER)?` line in `open_at`. In
  `text.rs`: `work_folder_not_empty`. Prove each unused with `git grep` before deleting, and say so.
- In `text.rs`: `API_KEY_SET`.

### 2.4 The check: `ask` and `status`

- `fn ask(&self, home: &Path, args: &[&str]) -> Result<Option<Vec<u8>>>`: `self.launch(home,
  false)?`, then `child::run(&mut launch.command(args), None, CHECK_TIMEOUT.min(self.timeout),
  CHECK_CAP, None)`; `Ok(Some(stdout))` on a successful finish, `Ok(None)` on any other way it ran.
  A launch error is `Err` (so a script `claude` gets `NOT_NATIVE`, not `DOES_NOT_RUN`).
- `status`: `--version` through `ask`; `Err` returned as it is, `Ok(None)` and a bad version stay
  `DOES_NOT_RUN`. `auth status --json` through `ask`; `Err` returned as it is; `Ok(None)` or an
  unreadable reply stays "not signed in", as today. Each of the two runs is its own launch (its own
  proxy and fresh run folder). `check` is unchanged apart from `Ready`'s shape.

### 2.5 A call

In `Provider::call`, keep every check before the launch as it is (the seal, `check_brief`, the
model name, the slash, the stop flag). Then:
1. `let (egress, launch) = self.launch(&home_of_session, false)?;` **before** `session.start`, so a
   `claude` that can't be launched leaves no ledger line. The home is the session's: add
   `pub(crate) fn home(&self) -> &Path` to `Session` if it has none.
2. `session.start` as today, then `launch.command(&[...])` with today's arguments **minus**
   `"--setting-sources", "project,local"` (the launch puts them first), `--max-budget-usd` as today.
3. `child::run` with the prompt, `self.timeout`, `STDOUT_CAP` and `self.stop`, as today; then drop
   the launch and stop the egress; then judging and the ledger exactly as today
   (`Ran::NotStarted` still discards the started line and answers `DOES_NOT_RUN`).

### 2.6 Signing in

```rust
/// Wait for Claude Code's login inside the sandbox; the sign-in page opens in the browser.
pub fn sign_in(&self, home: &Path, stop: &AtomicBool) -> Result<()>
/// `sign_in`, with the opener given (tests).
pub fn sign_in_with(
    &self,
    home: &Path,
    stop: &AtomicBool,
    open: &(dyn Fn(&str) -> std::io::Result<()> + Sync),
) -> Result<()>
```

`sign_in` is `sign_in_with(home, stop, &open_in_browser)`. `fn open_in_browser(link: &str) ->
std::io::Result<()>` (private): `Command::new("/usr/bin/open").arg(link)` with stdin, stdout and
stderr null, `.status()`; a non-zero exit is `Err(std::io::Error::other("open failed"))`. The link
is never printed, logged, put in an error, or returned.

`sign_in_with`:
1. `let (egress, launch) = self.launch(home, true)?;` and
   `launch.command(&["auth", "login", "--claudeai"])`.
2. Three local flags: `abort`, `done`, `refused` (`AtomicBool`, false).
3. In a `thread::scope`: spawn the watcher; run `child::run(&mut command, None,
   SIGN_IN_TIMEOUT.min(self.timeout), CHECK_CAP, Some(&abort))` on the current thread; then set
   `done`. The watcher loops until `done`, sleeping 50 ms per turn:
   - `stop` set: set `abort`, end.
   - The link not yet opened: `launch.sign_in_link()`. `NotYet`: go on. `Ready(link)`: mark it
     opened (never read or open a second link), call `open(&link)`; on `Err`, set `refused` and
     `abort`, end. `Refused`: set `refused` and `abort`, end.
4. Drop the launch, `egress.stop()`.
5. Map: `Finished` with success: `Ok(())`. `Finished` otherwise: `SIGN_IN_FAILED`. `CutOff`:
   `SIGN_IN_TIMED_OUT`. `Stopped` with `refused` set: `SIGN_IN_FAILED`. `Stopped` otherwise:
   `SIGN_IN_STOPPED`. `NotStarted`: `DOES_NOT_RUN`.

### 2.7 Ctrl-C in the terminal: `pub fn stop_on_interrupt() -> &'static AtomicBool`

The child runs in a process group of its own, so Ctrl-C reaches only the CLI; without this, a
killed CLI would leave the sandboxed `claude` waiting for its sign-in. In `claude.rs`: a private
`static INTERRUPTED: AtomicBool`; an `extern "C" fn` handler that only stores `true` into it
(`SeqCst`; nothing else, it runs in a signal handler); `stop_on_interrupt` installs it for
`SIGINT` with `libc::sigaction` (empty mask, `sa_flags` 0), once (a `std::sync::Once`), and returns
`&INTERRUPTED`. A `// SAFETY:` comment on the `unsafe` block, in the file's style.

### 2.8 The module doc

Add to the module comment, after its first paragraph: every `claude` runs inside the sandbox
(`sandbox::Launch`) with a proxy of its own (`egress::Egress`) and an environment built from
nothing, so no credential, provider switch or endpoint of the person's reaches it; see
`docs/spikes/VO11-os-sandbox.md`.

## 8. Fix after V1's run of `ci-local.sh` (outside the sandbox, on the § 1–7 tree)

`calls_in_flight_hold_their_budget` (`builder/agent/tests/cap.rs`) failed once in `ci-local.sh`
with `text::RUN_FOLDER_FAILED`: two calls on two threads launched at once, both found `runs/`
missing, both created it, and the loser's `create` failed with `AlreadyExists`. Now that every
check and call launches, two launches at once are ordinary (a status check during a build, a
panel's seats), so this is a real failure, not a test flake. `ensure_profile` in `claude.rs` has
the same shape for the app and profile folders.

1. `sandbox.rs`, `fresh_folder`: in the arm that creates the parent, an `AlreadyExists` error
   from `create` is not a failure; carry on to the `private_folder(&parent)?` check that already
   follows (which refuses a link, a non-folder, a shared mode, another owner or an ACL, whoever
   made it). Every other error is still returned.
2. `claude.rs`, `ensure_profile`: the same for each of the two folders: on `AlreadyExists` from
   `create`, read the path again with `symlink_metadata` and apply the existing checks (a real
   folder, not a link; mode tightened to 0700 when `& 0o077 != 0`), so a racing creator gets the
   same result as a folder that was already there.
3. Tests first, each red before its fix: in `builder/agent/tests/launch.rs` (macOS), 16 threads
   behind a `std::sync::Barrier` each call `Launch::new` with `RunFolder::Fresh` on one new
   private profile whose `runs/` doesn't exist yet: all 16 succeed, with 16 distinct run folders.
   In `builder/agent/tests/profile.rs`, 16 threads behind a `Barrier` each call
   `claude::find_in(home, None, &[<a stub program>])` on one new home: all 16 succeed. Run each new
   test 20 times (`for i in $(seq 20)`) before the fix and report how many runs went red; after
   the fix, 20 green.
4. Nothing else changes.
