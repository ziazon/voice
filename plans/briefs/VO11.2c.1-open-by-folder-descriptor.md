# VO11.2c.1 brief: open history files through the folder's descriptor

VO11.2c made the app read Claude Code history and the claude.ai download through `voice reader
<step>` under the reader profile. Its security review and Verifier left one gap, recorded as the
open residual in `.ai/SECURITY.md` (the row *The app's history reading is turned against it*):
inside a source, the reader lists a folder and then opens what it found **by path**. A folder
swapped for a symlink between the listing and the open is followed (under the profile, only to
places it already allows). This slice anchors every one of those opens to a descriptor of the
folder that was listed, and nothing else.

## The gap, as the code stands

- `mine.rs`: `project_folders(projects)` lists `~/.claude/projects` with `fs::read_dir`; then
  `session_files(&folder, …)` lists each project folder **by its path** (`fs::read_dir(folder)`),
  and `open_session(&path)` opens each session file **by its path** (`O_NOFOLLOW` guards only the
  last component). A project folder swapped for a link after `project_folders` listed it is
  followed by both. `folders()` (the `voice folders` rows) has the same listing gap.
- `claudeai.rs` `read_export_expected`: the chosen export is opened with `O_NOFOLLOW` (`open`),
  which for a folder already gives a descriptor of it, but the folder branch then lists it by path
  (`fs::read_dir(path)`, `fs::metadata(entry.path())`) and opens `path.join("conversations.json")`
  by path. The folder swapped for a link after the first open is followed.

## 1. `builder/ingest/src/folder.rs`: one descriptor-anchored folder type

New file, `pub(crate) mod folder;` in `builder/ingest/src/lib.rs` (keep the list alphabetical).
First line: `//! Descriptor-anchored folders: a folder renamed or swapped for a link after it is
opened can't redirect a read.`

**Move, don't copy,** `DirectoryStream` (with its `Drop`), both `errno()` functions and `open_at`
out of `skills/read.rs` into `folder.rs` as `pub(crate)`, and make `skills/read.rs` import them.
`skills/read.rs` changes in no other way.

```rust
pub(crate) struct Folder(File);
impl Folder {
    /// O_RDONLY | O_DIRECTORY | O_CLOEXEC, plus O_NOFOLLOW unless `follow`.
    pub(crate) fn open(path: &Path, follow: bool) -> std::io::Result<Folder>;
    /// A descriptor the caller already opened and checked is a folder.
    pub(crate) fn from_file(file: File) -> Folder;
    /// The folder's entry names, without "." and "..", in the order readdir gives them.
    pub(crate) fn names(&self) -> std::io::Result<Vec<CString>>;
    /// fstatat on the descriptor; AT_SYMLINK_NOFOLLOW unless `follow`.
    pub(crate) fn stat(&self, name: &CStr, follow: bool) -> std::io::Result<libc::stat>;
    /// open_at(fd, name, O_RDONLY | O_DIRECTORY): never through a link (open_at adds O_NOFOLLOW).
    pub(crate) fn folder(&self, name: &CStr) -> std::io::Result<Folder>;
    /// open_at(fd, name, O_RDONLY | flags): never through a link.
    pub(crate) fn file(&self, name: &CStr, flags: libc::c_int) -> std::io::Result<File>;
}
```

- `names()` must not consume or move the folder's own descriptor: open a fresh stream with
  `open_at(fd, c".", O_RDONLY | O_DIRECTORY)`, hand that to `fdopendir` (ownership passes to a
  `DirectoryStream`, as `skills/read.rs` does), loop `readdir` with the `errno` reset/check exactly
  as `walk` does, copy each name out. Calling `names()` twice gives the same list both times.
- An error is the `std::io::Error` from `last_os_error()`; callers map it.
- Unit tests in `folder.rs` (scratch folders from `std::env::temp_dir()` named with the process id
  and a counter, removed at the end; or include `../tests/common/mod.rs` as `mine.rs` does):
  1. `names()` lists a file, a subfolder and a symlink, twice, and never `.` or `..`.
  2. `stat(name, false)` of a symlink is `S_IFLNK`; `stat(name, true)` of a link to a file is
     `S_IFREG`; `st_nlink` is 2 after a hard link.
  3. `file()` of a symlink entry fails with `ELOOP`; `folder()` of a symlink to a folder fails with
     `ELOOP`; `folder()` of a file fails with `ENOTDIR`.
  4. **The anchor:** open folder `a` (holding `x` = `"first"`), rename `a` to `a-moved`, make a
     symlink `a` → folder `b` (holding `x` = `"second"`); `file(c"x", 0)` reads `"first"`.

## 2. `mine.rs`: list and open through descriptors

Add, private to `mine.rs`:

```rust
struct Entry { path: PathBuf, name: CString }   // path: for messages, the deny list and sorting only
```

- `project_folders(projects: &Path, root: &Folder) -> Result<Vec<Entry>>`: the same rules as today,
  in the same order, using `root.names()` and `root.stat(name, false)`: a symlink is `link(&path)`;
  a folder is kept after `name(&path)?`; anything else skipped; sorted by name as today.
- `open_projects(projects: &Path) -> Result<Folder>`: `Folder::open(projects, true)`. The projects
  root itself may still be a link (unchanged: the CLI's `--projects` and a person's own
  `~/.claude/projects` may be one; the reader's profile already resolves it). `NotFound` keeps
  today's exact message (`"{} doesn't exist: there is no Claude Code history there"`); any other
  error goes through `io(projects, …)`.
- `open_project(root: &Folder, entry: &Entry) -> Result<Folder>`: `root.folder(&entry.name)`;
  `ELOOP` is `link(&entry.path)`; any other error goes through `io(&entry.path, …)`.
- `session_files(folder_path: &Path, folder: &Folder, deny: &DenyList) -> Result<(Vec<Entry>, usize)>`:
  today's checks in today's order (the `.jsonl` suffix, `deny.denied(&path)`, `name(&path)?`, a
  symlink is `link(&path)`, not a regular file is `"{} is not a file"`, `st_nlink > 1` counts as
  denied and is skipped), with the kind and link count from `folder.stat(name, false)`; sorted by
  file name as today.
- `open_session(folder: &Folder, entry: &Entry) -> Result<Option<File>>`:
  `folder.file(&entry.name, libc::O_NONBLOCK)`; `ELOOP` is `link(&entry.path)`, any other error is
  `Error::Io { path: entry.path, … }`; then on the **opened** file, exactly as today: not a regular
  file is `"{} is not a file"`, `nlink() > 1` is `Ok(None)`.
- `mine_with_progress` and `folders` use them: open the root once, list it, and for each project
  folder (after the deny and filter checks it has today) `open_project`, `session_files`, then
  `open_session` per file. Everything else in both functions stays as it is (progress calls, counts,
  `Builder { path: &entry.path, … }`).
