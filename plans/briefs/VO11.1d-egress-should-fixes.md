## 1. A non-blocking accept, so `stop()` never needs a wake connection

Today `stop()` wakes the blocking `accept` by connecting to its own port, retrying until the
accept thread ends. When the process is out of file descriptors for reasons outside the proxy
(no proxy socket to free), every wake connect fails and `stop()` waits until something else frees
one. Remove the wake entirely:

1. In `start_with`, right after `bind`, call `listener.set_nonblocking(true)`; an error maps
   through the same `error` closure as `bind`'s.
2. In `accept()`, the existing `Err(_)` arm already does what is needed (stopped: `break`;
   otherwise sleep 10 ms and `continue`); `WouldBlock` now lands there on every idle poll. Keep
   it as one arm. Rewrite the comment above it, or add one, saying the listener is non-blocking,
   so this arm is also the idle poll that notices `stop()` within 10 ms.
3. **Set each accepted socket back to blocking:** right after `Ok(child)`, call
   `child.set_nonblocking(false)`; if that fails, drop the socket and `continue` (before the
   stopped check and before it takes a slot or an id in the registry). On macOS, `accept(2)` gives
   the new socket "the same properties" as the listener, so without this every handler's read
   returns `WouldBlock` at once; Linux does not inherit the flag, so this is for macOS.
4. `shutdown()`: set the flag; close the registered sockets; **join the accept thread** (no
   connect, no loop, no `is_finished` polling); close the registered sockets again; join the
   handlers. Delete the wake `connect_timeout` loop and the `address` it used. Remove any import
   that becomes unused.
5. Rewrite `stop()`'s doc comment to match: it stops new work, closes the registered sockets,
   waits for the accept thread (which polls the flag every 10 ms, so it needs no connection to
   wake), closes the sockets again (one accepted just before the flag) and joins the handlers;
   keep the sentence that a dial already under way finishes within its deadline, so `stop()`
   returns within about `dial_time` at worst.

## 2. A Drop guard for the resolvers-in-flight count

Today `dial()` increments `resolving` with `fetch_update`, and the helper thread decrements it
after `resolve` returns. A resolver that panics never decrements, so its slot is lost for the
proxy's life (16 panics and every later CONNECT gets `502`). Spawn failure decrements by hand.

1. Add a private guard type next to `dial()`, for example
   `struct Resolving(Arc<AtomicUsize>);` with `impl Drop` doing `fetch_sub(1, SeqCst)`, and a
   one-line comment: it gives the slot back when the resolver returns, panics, or never starts.
2. In `dial()`: after the `fetch_update` succeeds, make the guard from `resolving.clone()`. Move it
   into the helper closure; inside, `let result = resolve(&host); drop(slot); let _ = send.send(result);`
   (the slot is given back when `resolve` returns, before the send, as today). Delete the
   `running` clone and the manual `fetch_sub` in the spawn's `map_err` (a failed spawn drops the
   closure, and with it the guard). Keep `fetch_update`'s cap check exactly as it is.
3. Update the comment above the spawn if it no longer reads true.

## 3. A deterministic no-connection case in `tests/egress_descriptors.rs`

The existing test opens four half-read clients before exhausting descriptors, so `stop()`'s first
socket sweep frees descriptors and the old single-wake bug was caught only 2 runs in 6. Add a
second test that needs no luck:

1. `stop_with_no_connections_and_no_descriptors`: `Egress::start()`; open **no** client; lower the
   soft `RLIMIT_NOFILE` to the descriptors open now plus 4 (as the existing test does, `.min()` of
   the current soft limit); open `/dev/null` until `open` fails with `EMFILE`; call `stop()` on a
   thread and assert it returns within 3 s (`mpsc` + `recv_timeout`, the existing test's shape);
   then drop the fillers, restore the limit, and join the thread. With today's code nothing
   frees a descriptor, so every wake connect fails and `stop()` waits: this test must be red on
   `origin/main`'s `egress.rs` and green after § 1.
2. **The two tests in this file share one process, and the limit is process-wide**, while cargo
   runs a file's tests on parallel threads. Serialise them: a `static LIMITS: Mutex<()>` at the top
   of the file, locked first thing in each test for its whole body, with
   `.lock().unwrap_or_else(|poisoned| poisoned.into_inner())` so one failed test doesn't fail the
   other on a poisoned lock. One comment line on the static saying why.
3. Factor the shared steps only if it reads better (lower the limit and fill to `EMFILE`; stop on
   a thread with a deadline). Keep each `unsafe` block's `// SAFETY:` line. Don't change what the
   existing test asserts.

## 4. A wider `idle` in `one_way_traffic_keeps_both_reads_alive`

At load ~20 it flaked once in 16: a tick delayed past `idle` (600 ms, ticks every 200 ms) closed
the tunnel. Widen the slack while keeping the claim (only upstream → child moves bytes, and the
tunnel stays open well past `3 * idle` because both directions share one clock):

- `short.idle = Duration::from_millis(1200)`;
- 20 ticks of 200 ms (was 12);
- the end assertion `started.elapsed() > short_idle * 3` (3.6 s), with `idle` read into a local
  before `short` moves into `start_with`, in place of the literal 2100 ms.

Nothing else in that test changes.
