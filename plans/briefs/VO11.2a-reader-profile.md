# VO11.2a brief: the reader's profile and launch, as a library

VO11 put the person's own Claude Code in a Seatbelt sandbox, and VO11.1 wired it in. VO11.2 moves
the app's *reading* (Claude Code history, a claude.ai export, skill folders) out of the app's own
process into the shipped `voice` command, run in a sandbox of its own: it may read only the sources
the person agreed to plus the assistant's own folders, and it has no network, no Keychain and no
other program. VO11.2 is split in four (lane V's spec, *VO11.2*): this slice, **VO11.2a, builds the
reader's sandbox profile and a library that builds one sandboxed reader launch, with tests.** It
wires nothing in: no caller, no CLI subcommand, no app change. VO11.2b adds the `voice reader`
mode and the hard-link refusal; VO11.2c wires the app.

Read first: `AGENTS.md`, `.ai/PROJECT.md`, `.ai/SECURITY.md`, `CONTRIBUTING.md`,
`docs/spikes/VO11-os-sandbox.md`, then `builder/agent/src/sandbox.rs`,
`builder/agent/sandbox/claude-code.sb` and `builder/agent/tests/sandbox_profile.rs`: this slice
copies their shape. Skills: `~/.codex/skills/tdd-skill/SKILL.md`,
`~/.codex/skills/security-and-hardening/SKILL.md`, `~/.codex/skills/code-quality/SKILL.md`,
`~/.codex/skills/source-driven-development/SKILL.md`, `~/.codex/skills/plain-language/SKILL.md`
(every sentence a person reads).

This is a public repo: invented names only, no real person, no fixed paths, no real secret in any
fixture. Add no dependency. Match the surrounding code: its comment density, naming, and the
`voice_core::error::{Error, Result}` and `Error::Invalid(text::…)` idiom. Commit nothing; leave
every change in the working tree.

**Your own sandbox:** you run inside a Seatbelt sandbox, and macOS refuses a sandbox inside a
sandbox. Every test that runs `/usr/bin/sandbox-exec` must use the same skip as
`sandbox_profile.rs` (`available()`: skip with a printed line, fail when
`VOICE_REQUIRE_SANDBOX=1`). Those tests will skip for you: make them compile and pass clippy, run
them once to see the skip line, and say so in your summary. V1 runs them outside, so write them
carefully: you can't see them run.

## What V1 measured on Mimi, 2026-11-02, macOS 27.0.1 (don't re-derive it)

With `(deny default)`, `(import "system.sb")`, the system reads of `claude-code.sb` and
`(allow file-read* (subpath <folder>))` for one folder:

- `/bin/realpath <folder>/sub/f` is **refused** (`Operation not permitted`): resolving a path needs
  metadata reads on every folder above it, which `(deny default)` refuses.
- Adding `(allow file-read-metadata (literal "/") (literal "/private") (literal "/private/tmp")
  (literal <the folder's parent>))` makes `realpath` work, through the `/tmp` link too, while
  `ls <the parent>` and `cat <a sibling file of the folder>` stay refused. So metadata-only rules
  on each folder above an allowed path are enough, and they don't open the parent's listing or a
  sibling's content.
- With the same metadata-only rules, a small C program walking `/` down with
  `openat(…, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)` is refused at the first folder above the source
  (`private`), while the same walk with `O_SEARCH|O_DIRECTORY|O_NOFOLLOW` opens every folder
  down to the source and then the file inside it. So a descriptor-anchored walk works under this
  profile only if it opens the folders above an allowed path with `O_SEARCH`. That is VO11.2b's
  to apply to `ingest/src/private.rs`; nothing in this slice changes it.
- Everything in the spike report still holds: the last matching rule wins, so the secrets denies go
  after every allow; Seatbelt checks the real path, so a symlink inside an allowed folder to a file
  outside is refused, but a **hard link** inside an allowed folder to a file outside is readable;
  a sandboxed process can't make a hard link to a file outside; a missing `-D` parameter makes
  `sandbox-exec` exit 65.

## 1. The profile template: `builder/agent/sandbox/reader.sb` (new)

Exactly this, comments included:

```
(version 1)
(deny default)
(import "system.sb")
; Voice's reader needs no certificate service, which can reach the network.
(deny mach-lookup (global-name "com.apple.trustd") (global-name "com.apple.trustd.agent"))

; The reader is the program itself and starts nothing else.
(allow process-exec (literal (param "PROGRAM")))
(allow signal (target self))
(allow process-info* (target self))

; Read only the system code and devices needed to run, the program file, the assistant's own
; folders, this run's folder, and the sources the person agreed to (below). The caller gives
; absolute paths with links resolved.
(allow file-read*
    (subpath "/usr/bin")
    (subpath "/usr/lib")
    (subpath "/usr/libexec")
    (subpath "/usr/sbin")
    (subpath "/usr/share")
    (subpath "/System")
    (subpath "/private/etc")
    (literal "/dev/null")
    (literal "/dev/zero")
    (literal "/dev/random")
    (literal "/dev/urandom")
    (literal "/dev/dtracehelper")
    (subpath "/dev/fd")
    (literal (param "PROGRAM"))
    (subpath (param "MEMBER_DIR"))
    (subpath (param "STATE_DIR"))
    (subpath (param "RUN_DIR")))

; Only the assistant's private state and this run may change.
(allow file-write*
    (subpath (param "STATE_DIR"))
    (subpath (param "RUN_DIR"))
    (literal "/dev/null"))
; The two folders themselves can't be moved, removed, replaced or changed; their contents can.
(deny file-write* (literal (param "STATE_DIR")) (literal (param "RUN_DIR")))

; No network of any kind: no rule allows it.

;; sources

; These rules follow the allows so password and key files stay closed even
; inside an allowed folder. Match whole components, in either letter case.
; macOS 27 ignores regex letter case; the letter classes keep these rules right
; if a later macOS starts matching case.
; Keep one rule per built-in name or sequence in core/src/deny.rs.
(deny file-read* file-write*
    <copy the 17 regex lines of claude-code.sb's block here, byte for byte>)
```

- The deny block (from the line `; These rules follow the allows` to the `)` closing the
  `(deny file-read* file-write* …)` form) is **byte-identical** to `claude-code.sb`'s. There is
  **no** `.credentials.json` exception in this profile and no sign-in rule: the reader never needs
  Claude Code's login.
- `;; sources` is the marker line the library replaces (§ 2.3). It appears exactly once.
- Note there is no `process-fork`: the reader starts nothing.

## 2. The library: `builder/agent/src/reader.rs` (new), `pub mod reader;` in `lib.rs`

Module doc: one sandboxed run of Voice's own reader, the shipped `voice` command; see
`docs/spikes/VO11-os-sandbox.md`.

### 2.1 Types

```rust
pub const MAX_SOURCES: usize = 64;

/// A place the person agreed Voice may read, as the caller found it.
pub enum Source<'a> {
    Folder(&'a Path),
    File(&'a Path),
}

pub struct Reader { /* program, member, state, run, sources: Vec<(bool /*folder*/, PathBuf)>, ancestors: Vec<PathBuf>, home */ }

impl Reader {
    pub fn new(program: &Path, home: &Path, member: &Path, state: &Path, runs: &Path,
               sources: &[Source<'_>]) -> Result<Reader>;
    pub fn run_folder(&self) -> &Path;
    pub fn profile(&self) -> String;          // the generated profile text (§ 2.3)
    pub fn command(&self, args: &[&str]) -> Command;
}
impl Drop for Reader { /* remove the run folder, as Launch does for Fresh */ }
```

Off a Mac (`#[cfg(not(target_os = "macos"))]`), `Reader::new` returns
`Err(Error::Invalid(text::MAC_ONLY.into()))`, as `Launch::new` does.

### 2.2 `Reader::new`, in this order (macOS)

1. `program`: `sandbox::resolve_program(program)` (links resolved, a regular executable Mach-O
   file). **No `test-stubs` bypass**: the reader is Voice's own native program, and tests use
   native system programs. On error return its error unchanged.
2. `member`: `fs::canonicalize`, must be a directory. `state`: must pass `private_folder` before
   and after `fs::canonicalize` (as `Launch::new` does for the profile folder). Any failure:
   `Err(Error::Invalid(text::READER_FOLDER.into()))`.
3. `sources`: at most `MAX_SOURCES`, else `text::READER_SOURCE`. Each must be absolute; canonicalize
   it; `Folder` must then be a directory and `File` a regular file (by `fs::metadata` on the
   canonical path); and neither the given nor the canonical path may be denied by
   `voice_core::deny::DenyList::builtin().denied(…)`. Any failure: `text::READER_SOURCE`. Keep the
   canonical paths in the order given; drop exact duplicates (same kind and same path).
4. The run folder: a fresh 0700 folder inside `runs`, made exactly as `Launch` makes a `Fresh` run
   folder. Refactor in `sandbox.rs`: `fresh_folder(profile)` becomes a call to a new
   `pub(crate) fn fresh_folder_in(parent: &Path)` holding today's body with `parent` given, and
   `private_folder` becomes `pub(crate)`. `Launch`'s behaviour must not change. Failure:
   `text::RUN_FOLDER_FAILED`.
5. Ancestors: every proper ancestor (from `/` down, `/` included) of the program, the member,
   state and run folders and every source, all canonical; de-duplicated and sorted. Any path that
   is itself one of the allowed paths stays in the list too (a metadata read on it is already
   allowed; it does no harm).

### 2.3 `Reader::profile()`

The template (`include_str!("../sandbox/reader.sb")`) with the marker line `;; sources` replaced
(once) by generated lines, and nothing else changed. **No path is ever written into the profile
text**: every path goes in as a `-D` parameter, so a folder name holding `"`, `)` or a line break
can't change the rules. The generated lines, in this exact form:

```
; Sources the person agreed to, read-only.
(allow file-read*
    (subpath (param "SOURCE_0"))
    (literal (param "SOURCE_1")))
; The folders above each allowed path, metadata only, so the reader can resolve paths.
(allow file-read-metadata
    (literal (param "ANCESTOR_0"))
    (literal (param "ANCESTOR_1")))
```

`subpath` for a `Folder`, `literal` for a `File`, numbered in the order kept in § 2.2 step 3. When
there are no sources, leave out the first form (its comment too). There is always at least one
ancestor (`/`).

### 2.4 `Reader::command(args)`

`/usr/bin/sandbox-exec -p <profile()> -D PROGRAM=<program> -D MEMBER_DIR=<member>
-D STATE_DIR=<state> -D RUN_DIR=<run> -D SOURCE_<n>=<path>… -D ANCESTOR_<n>=<path>… <program>
<args…>`, with `OsString` parameters as `Launch::command` builds them (never `to_str` a path),
`current_dir` the run folder, and the environment built from nothing: `env_clear()`, then `HOME`,
`USER` and `LOGNAME` (from `login_name()`, when known), `PATH=/usr/bin:/bin:/usr/sbin:/sbin`,
`LANG` (from `language()`), and `TMPDIR` = the run folder plus `/`. Nothing else: no proxy, no
`CLAUDE_*`. Make `login_name` and `language` in `sandbox.rs` `pub(crate)` and reuse them; don't
copy them.

### 2.5 Text (`builder/agent/src/text.rs`)

```rust
pub const READER_SOURCE: &str = "Voice can't read one of the places you chose. Check it's still there and isn't a password or key file, then try again.";
pub const READER_FOLDER: &str = "Voice couldn't open this assistant's own folders. Close Voice and open it again.";
```

## 3. Tests: `builder/agent/tests/reader_profile.rs` (new), `#![cfg(target_os = "macos")]`

Use `mod common;` and `common::Scratch` for every folder, the `available()` skip copied from
`sandbox_profile.rs`, and the same `CANARIES` list. Every sandbox test builds its command through
`Reader::command`, so the generated profile is what's tested. Each test writes the word `canary`
into its canary files. A helper `run(reader, args) -> Output` runs `reader.command(args)` with
`output()`. The program is a system program chosen per test (`/bin/cat`, `/bin/ls`,
`/bin/realpath`, `/usr/bin/touch`, `/bin/ln`, `/bin/bash`, `/usr/bin/nc`): pass it as `program`
to `Reader::new`, and the args as `command`'s args (the program is not repeated in args).

Red first: write the tests against a `Reader` whose `command` returns
`Command::new("/usr/bin/false")`, see them fail on their assertions (where they run), then build.

Sandbox tests (each starts with `if !available() { return; }`):

1. **Sources are readable, nothing else is.** A folder source with `sub/f` and a file source
   `one/g` (in a different scratch folder, whose sibling `one/h` is not a source): `cat` of
   `sub/f` and of `g` print `canary`; `ls` of the folder source works; `cat` of `h`, of a file in
   an unrelated scratch folder, and `ls` of the file source's parent folder are refused (nonzero
   exit, no `canary` on stdout).
2. **Paths resolve.** `/bin/realpath <folder source>/sub/f` prints that path and exits 0;
   `/bin/realpath` of the file source works too.
3. **Writes go only to the state and run folders.** `touch` a new file in the state folder and
   the run folder: both work. `touch` in the member folder, in a folder source, and in an
   unrelated scratch folder: all refused, and the file does not exist afterwards.
4. **Secrets stay closed inside a source and the state folder.** For every `CANARIES` entry, and
   for its upper-case form, placed inside the folder source and inside the state folder: `cat`
   refused. Also a `File` source whose name is a canary (`real.pem`) is refused by `Reader::new`
   (§ 5 below).
5. **No network.** A TCP listener on `127.0.0.1:0` in the test: `/usr/bin/nc -z -w1 127.0.0.1
   <port>` exits nonzero and the listener sees no connection; `nc -u -w1 127.0.0.1 <port>` with
   stdin `x` never reaches a UDP socket bound in the test on that port (read with a 1 s timeout);
   a Unix socket listener in a scratch folder given as a source: `nc -U <path>` fails and no
   connection arrives. Copy how `sandbox_profile.rs` sets these up.
6. **No other program.** Program `/bin/bash`, args `-c "/bin/echo started"`: exits nonzero and
   stdout lacks `started`.
7. **Hard links, pinned.** In the folder source, `link` hard-linked (`fs::hard_link`, made by the
   test outside the sandbox) to a canary file in an unrelated scratch folder: `cat` of `link`
   **prints `canary`**. Assert it, with a comment: Seatbelt checks the path, not the file, so the
   reader's own refusal (VO11.2b) is the control; if this assertion ever fails, macOS started
   checking the file, and the spike report and SECURITY.md should say so. Then the sandboxed
   `/bin/ln <canary outside> <state folder>/made` is refused and `made` does not exist.
8. **A path can't change the rules.** A folder source whose name is `a") (allow default) ;"` and a
   second one whose name holds a line break: each readable through the sandbox, an unrelated
   scratch file still refused, and `reader.profile()` contains neither name nor any source's path
   text (assert for every source and ancestor path that `profile()` does not contain it, except
   `/`, which can't be tested that way: skip `/`).

Tests that need no sandbox (no `available()` call):

9. **The profile.** `profile()` holds the marker's replacement and no `;; sources` line; with no
   sources it has no `SOURCE_` text; with two sources it has `SOURCE_0` and `SOURCE_1` as
   `subpath`/`literal` by kind; the deny block of `reader.sb` (from `; These rules follow the
   allows` through the closing of its form) equals `claude-code.sb`'s byte for byte; `reader.sb`
   has no `network`, `process-fork` or `.credentials.json` text outside comments.
10. **`Reader::new` refuses**, each with `text::READER_SOURCE`: a relative source path; a missing
    one; `MAX_SOURCES + 1` sources; a `Folder` that is a file and a `File` that is a folder; a
    folder named `.ssh`; a file named `real.pem`; a symlink whose target is named `real.key`.
    With `text::READER_FOLDER`: a state folder that is 0755, and a member path that is a file.
    A program that is a `#!` script: the `resolve_program` error (`text::NOT_NATIVE`).
11. **The run folder.** `run_folder()` is inside `runs`, mode 0700, empty, and is gone after the
    `Reader` drops. Duplicate sources appear once in `profile()`.
12. **The environment.** `command(&[])`'s `get_envs()` names exactly `HOME`, `PATH`, `LANG`,
    `TMPDIR`, and `USER` and `LOGNAME` when known, each with a value; `get_program()` is
    `/usr/bin/sandbox-exec` and the first two args are `-p` and `profile()`. Whether the
    environment is cleared is covered by a sandbox test instead: program `/usr/bin/env` (add it to
    tests 1's style), run through `run`, prints only those names (compare the `NAME=` prefixes of
    its lines, sorted).

## 6. The review's fixes (V1, 2026-11-02, after the security review and the Verifier)

Both passed the slice with these to fix first. Change only `builder/agent/src/reader.rs`,
`builder/agent/tests/reader_profile.rs` and `docs/spikes/VO11-os-sandbox.md`; commit nothing.

1. **The person's own deny list.** `Reader::new` gains a last parameter `deny: &DenyList`
   (`voice_core::deny::DenyList`): the caller passes `DenyList::for_member(…)`. In § 2.2 step 3,
   a source is refused (`text::READER_SOURCE`) when the given or canonical path is denied by
   `DenyList::builtin()` **or** by `deny`. Keep the built-in check even if the caller's list
   already holds it. Test 10 gains: a list made with `DenyList::new(home, &["diary".into()])`
   refuses a folder source named `diary`, and the same source is accepted with
   `DenyList::builtin()`. Update every `Reader::new` call in the tests (pass
   `&DenyList::builtin()` where nothing else is meant).
2. **No source that is too broad, and no folder inside another.** In § 2.2, after canonicalising,
   refuse with `text::READER_SOURCE` a source that is `/`, the home folder (canonicalised), or a
   proper ancestor of the canonical home, member, state or runs folder; and a source equal to or
   inside the canonical state or runs folder (those are the reader's own, never a source). Refuse
   with `text::READER_FOLDER` a member folder equal to, inside, or containing the state folder,
   and a member or state folder equal to, inside, or containing the canonical runs folder
   (canonicalise `runs` for this check; it may not exist yet, so check its canonical parent plus
   its name). Compare with `Path::starts_with` on canonical paths. Test 10 gains one case for each
   rule: source `/`, source = home (use the `Folders` home scratch as `home`), source = the parent
   of the state folder, source = the state folder, source inside the runs folder, member inside
   state, state inside member, runs inside state.
3. **Never an empty metadata rule.** If the ancestors list is empty, `Reader::new` returns
   `text::RUN_FOLDER_FAILED` (it can't happen: the program always has `/` above it; this keeps a
   filterless `(allow file-read-metadata)`, which would allow every path, from ever being written).
   Also make `profile()` itself never emit the metadata form with no filter (if `ancestors` is
   empty, emit nothing for it).
4. **Two tests the reviews found missing.** (a) `trustd_is_refused`: port
   `trustd_services_are_refused_only_under_the_profile` from `sandbox_profile.rs` (the same `cc`
   skip, the same C program), run through `Reader::command` with the compiled program as the
   reader's program: it exits 1 under the profile, and 0 when run directly. (b) In
   `hard_links_are_pinned`, also: the sandboxed `/bin/ln` of a file **inside the folder source**
   to `<state>/made-source` and of a file **inside the member folder** to `<state>/made-member`:
   both refused, neither exists afterwards.
5. **The spike paragraph.** Say the metadata-only rules let the reader resolve paths "without
   listing those folders (other than `/`, which the system profile already lists)", and add one
   sentence: the caller gives the reader only stdin, stdout and stderr, as pipes or `/dev/null`,
   since `/dev/fd` is readable inside the sandbox and a file it can't open by path can't be written
   through a redirected stdout either.
