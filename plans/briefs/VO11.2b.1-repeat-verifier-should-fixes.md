## 1. `find` matches `list` for a linked folder whose target has another name

`assistants::find` skips its canonical-name check when the crew folder entry is a symlink
(`builder/core/src/assistants.rs`, the `symlink_metadata(..).is_ok_and(|m| !m.file_type().is_symlink())`
condition), so that it agrees with `list`, which follows links (`list_follows_links_and_breaks_name_ties_by_slug`).
No test covers that today: a mutation that drops the `!is_symlink()` part, applying the
canonical-name check to links too, passes every test.

Extend the existing test `find_matches_list_without_listing_crew` (do not add a new test fn):

1. After the `linked` setup and before the `for slug in [...]` loop, make a second assistant in the
   existing `outside` scratch home: `make(outside.path(), &input("Aliased"), "2026-10-25", "voice")`
   (its slug is `aliased`). Rename its folder to a sibling named `elsewhere`
   (`fs::rename(&aliased.dir, crew_dir(outside.path()).join("elsewhere"))`), then create
   `crew.join("aliased")` as a `std::os::unix::fs::symlink` to that `elsewhere` folder. The link's
   name is the slug; its target's name is not.
2. Add `"aliased"` to the slugs the loop compares (after `"linked"`).
3. After the loop, so the comparison isn't two `None`s, assert `find` finds it, with the dir being
   the link's own path, not the target:
   `assert_eq!(find(home.path(), "aliased").unwrap().map(|l| l.dir), Some(crew.join("aliased")));`

Red check (do this and report it): temporarily remove `!metadata.file_type().is_symlink()` from
`find`'s condition (so it reads `fs::symlink_metadata(&dir).is_ok() && !fs::canonicalize(...)...`),
run the test and confirm it fails on the `aliased` case; restore the line exactly
(`git diff builder/core/src/assistants.rs` must show test lines only).
