# VO11.1b brief: the sandboxed launch, as a library

VO11 landed a Seatbelt profile for the `claude` child (`builder/agent/sandbox/claude-code.sb`),
its tests (`builder/agent/tests/sandbox_profile.rs`) and a probe
(`scripts/claude_sandbox_probe.py`). The owner chose where the login lives (V-Q10, option 1):
inside the sandbox Claude Code keeps it as `.credentials.json` in Voice's own 0700 profile folder,
never the Keychain. This slice tightens the profile and lands **a library that builds one
sandboxed `claude` launch**: the command, its environment, its run folder, and the sign-in link
hand-off. It does **not** wire the library into `claude.rs` or any caller: that is VO11.1c. The
egress proxy is VO11.1a, also not yours: this library takes the proxy's port as a number.

Read first: `AGENTS.md`, `.ai/PROJECT.md`, `.ai/SECURITY.md`, `CONTRIBUTING.md`,
`docs/spikes/VO11-os-sandbox.md`. Skills: `~/.codex/skills/tdd-skill/SKILL.md`,
`~/.codex/skills/security-and-hardening/SKILL.md`, `~/.codex/skills/code-quality/SKILL.md`,
`~/.codex/skills/source-driven-development/SKILL.md`, `~/.codex/skills/plain-language/SKILL.md`
(every sentence a person reads).

This is a public repo: invented names only, no real person, no fixed paths, no real secret in any
fixture. Add no dependency (Rust or Python; `libc` is already a dependency of `voice-agent`).
Python must run on 3.9. Match the surrounding code: its comment density, its naming, its
`voice_core::error::{Error, Result}` and `Error::Invalid(text::…)` idiom. Commit nothing; leave
every change in the working tree.

**Your own sandbox:** you run inside a Seatbelt sandbox, and macOS refuses a sandbox inside a
sandbox. Every test that runs `/usr/bin/sandbox-exec` must use the existing skip
(`available()` in `sandbox_profile.rs`: skip with a printed line, fail when
`VOICE_REQUIRE_SANDBOX=1`). Those tests will skip for you: build them so they compile and pass
clippy, run them once to see the skip line, and say so in your summary. V1 runs them outside.

## What V1 measured on Mimi, 2026-11-01, macOS 27.0.1, Claude Code 2.1.292 (don't re-derive it)

All with the profile changes in § 1 applied, an environment built from nothing (§ 2.3), and a
throwaway profile folder:

- `claude --setting-sources project,local --version` prints `2.1.292 (Claude Code)`;
  `claude --setting-sources project,local auth status --json` works. **Placed after the
  subcommand** (`claude auth status --json --setting-sources project,local`) Claude Code refuses
  it: `error: unknown option '--setting-sources'`. So the flag always goes first.
- With `process-exec` allowed only for the program, `--version`, `auth status`, a signed-out `-p`
  (`Not logged in · Please run /login`), and an `auth status` reading an invented
  `.credentials.json` (`loggedIn: true`, so Claude Code reads the file login without running
  `/usr/bin/security`) all work.
- With `com.apple.trustd` and `com.apple.trustd.agent` denied, a `-p` with an invented token went
  through a CONNECT proxy to `api.anthropic.com` and came back `401 Invalid bearer token`: TLS
  held, so Claude Code carries its own roots. `nscurl` fails certificate checks under the same
  deny, so the deny does bite.
- Reads of the program allowed as `(literal <program>)` alone (not its folder) are enough for all
  of the above.
- **The sign-in link.** `claude auth login --claudeai` prints `If the browser didn't open, visit:
  https://claude.com/cai/oauth/authorize?…` on **stdout**, but that printed link is the
  paste-a-code one (`redirect_uri=https://platform.claude.com/oauth/code/callback`). Claude Code
  runs `$BROWSER <link>` with the **localhost-callback** link
  (`redirect_uri=http://localhost:<port>/callback`), which is the one to open. With `BROWSER` set
  to a `#!/bin/bash` helper in the run folder (the script in § 2.5) and `process-exec` allowed for
  that helper and `/bin/bash` only while `SIGN_IN=yes`, the helper wrote the link into the run
  folder (mode 0600). With `SIGN_IN=no` Claude Code can't listen, so it never gets that far
  (`Failed to start OAuth callback server`). `/bin/sh` is a shim that reads
  `/private/var/select/sh` and runs `/bin/bash`, which is why the helper names `/bin/bash`
  directly.
- Current npm installs put the same native binary in place ("The installed `claude` binary does
  not itself invoke Node", `https://code.claude.com/docs/en/setup`, read 2026-11-01). An older
  npm install is a `#!/usr/bin/env node` script: its `node` lives outside anything the profile
  allows, so it can't run inside the sandbox.
- `DISABLE_AUTOUPDATER=1` turns off the background update check (same page). Inside the
  sandbox an update could neither download nor write, so it is set to keep Claude Code from trying.

## 2. The library: `builder/agent/src/sandbox.rs` (`pub mod sandbox;` in `lib.rs`)

Module doc: one short paragraph saying what it is (one sandboxed launch of the person's own
Claude Code), citing `docs/spikes/VO11-os-sandbox.md` and the two pages read
(`https://code.claude.com/docs/en/setup`, `https://code.claude.com/docs/en/network-config`).

The profile is compiled in: `const PROFILE: &str = include_str!("../sandbox/claude-code.sb");`
and passed with `-p`, so the app needs no file on disk.

### 2.1 The public surface

```rust
pub const SANDBOX_EXEC: &str = "/usr/bin/sandbox-exec";
pub const HELPER: &str = "open-sign-in";      // file name in the run folder
pub const LINK: &str = "sign-in-link";        // file name the helper writes
pub const MAX_LINK: usize = 4096;

/// Where a launch runs: a fresh folder made (and removed) by the launch, or a folder the caller
/// owns (a call's work folder), which is left in place.
pub enum RunFolder<'a> { Fresh, Given(&'a Path) }

pub struct Launch { /* program, profile, run, port, sign_in, home, fresh: bool */ }

/// The sign-in link, as the helper left it.
#[derive(Debug, PartialEq, Eq)]
pub enum Link { NotYet, Ready(String), Refused }

/// The folder that holds fresh run folders: `runs` beside the profile folder
/// (`<app folder>/runs`).
pub fn runs_folder(profile: &Path) -> PathBuf;

/// The program with links resolved, if it is something Voice can run in the sandbox.
pub fn resolve_program(program: &Path) -> Result<PathBuf>;

/// Whether `link` is a sign-in page Voice may open.
pub fn valid_link(link: &str) -> bool;

impl Launch {
    pub fn new(program: &Path, profile: &Path, home: &Path, run: RunFolder<'_>, proxy_port: u16,
               sign_in: bool) -> Result<Launch>;
    pub fn run_folder(&self) -> &Path;
    /// `/usr/bin/sandbox-exec -p <profile> -D … <program> --setting-sources project,local <args…>`,
    /// in the run folder, with the environment of § 2.3 and nothing else.
    pub fn command(&self, args: &[&str]) -> Command;
    /// Read the link once: `Ready` removes the file, so a link is handed out at most once.
    pub fn sign_in_link(&self) -> Link;
}
impl Drop for Launch { /* a Fresh run folder is removed (std::fs::remove_dir_all); Given is left */ }
```

Off macOS (`#[cfg(not(target_os = "macos"))]`), `Launch::new` returns
`Err(Error::Invalid(text::MAC_ONLY.into()))` and does nothing else; the module must still compile
on Linux and Windows (`resolve_program`, `valid_link`, `runs_folder` are plain code).

### 2.2 `Launch::new`, in this order

1. `proxy_port` 0 is `Error::Invalid` (a programming mistake: message
   `"the proxy port must be set"`).
2. `program = resolve_program(program)?`.
3. `profile`: `fs::canonicalize`; must be a directory (`symlink_metadata` of the canonical path,
   not a link) with mode `& 0o077 == 0`; else `Error::Invalid(text::PROFILE_FAILED)`.
   `.credentials.json` sits directly in it, so the profile's literal rule must match the real path.
4. The run folder:
   - `Fresh`: the parent is `runs_folder(&profile)`. Create it if missing with
     `DirBuilder::new().mode(0o700)`; if it exists it must be a real directory (not a link), and
     its mode is tightened to 0700 when `& 0o077 != 0` (the `ensure_profile` pattern in
     `claude.rs`). Then create `<parent>/<pid>-<n>-<nanos>` with `DirBuilder` mode 0700 and
     `create` (not `create_all`), `n` from a static `AtomicU64`, retrying the next `n` on
     `AlreadyExists`. Canonicalize it.
   - `Given(path)`: `fs::canonicalize(path)`; must be a real directory with mode `& 0o077 == 0`.
   - Any failure: `Error::Invalid(text::RUN_FOLDER_FAILED)`.
5. When `sign_in`: write the helper (§ 2.5) to `<run>/open-sign-in` with `OpenOptions`
   `write(true).create_new(true).mode(0o700)` and `custom_flags(libc::O_NOFOLLOW)`. Failure is
   `RUN_FOLDER_FAILED` (and a Fresh folder is removed, which `Drop` does once the struct exists:
   build the struct before writing so an error path drops it).

### 2.3 `Launch::command`: the argv and the environment

```
/usr/bin/sandbox-exec -p <PROFILE>
  -D PROGRAM=<program> -D PROFILE_DIR=<profile> -D RUN_DIR=<run> -D PROXY_PORT=<port>
  -D SIGN_IN=<yes|no>
  <program> --setting-sources project,local <args…>
```

`current_dir(run)`. `env_clear()`, then exactly these, and no other:

| Name | Value |
| --- | --- |
| `HOME` | `home` as given |
| `USER`, `LOGNAME` | the login name from `libc::getpwuid_r(libc::getuid(), …)` (a buffer from `libc::sysconf(_SC_GETPW_R_SIZE_MAX)`, 4096 when that is −1); left out when it can't be read or isn't valid UTF-8 |
| `PATH` | `/usr/bin:/bin:/usr/sbin:/sbin` |
| `LANG` | the parent's `LANG` when it is 1 to 64 of `A-Za-z0-9_.@-`, else `en_US.UTF-8` |
| `CLAUDE_CONFIG_DIR` | the profile folder |
| `CLAUDE_CODE_TMPDIR` | the run folder |
| `TMPDIR` | the run folder followed by `/` |
| `HTTPS_PROXY`, `https_proxy` | `http://127.0.0.1:<port>` |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | `1` |
| `DISABLE_AUTOUPDATER` | `1` |
| `BROWSER` | only when `sign_in`: `<run>/open-sign-in` |

Nothing from the parent passes through except `LANG` as above: no `ANTHROPIC_*`, no
`CLAUDE_CODE_*` of the person's, no `NODE_*`, no `SSH_AUTH_SOCK`, no proxy settings of the
person's. Write the table's reason in one comment: the child gets only what it needs, so no
credential, provider switch or endpoint of the person's reaches it (PB-D9).

### 2.4 `resolve_program`

1. `fs::canonicalize(program)`; failure is `Error::Invalid(text::DOES_NOT_RUN)`.
2. `fs::metadata` of the canonical path: a regular file with an execute bit (`mode & 0o111 != 0`),
   else `DOES_NOT_RUN`.
3. Read its first 4 bytes. Accept only Mach-O: `[0xcf,0xfa,0xed,0xfe]` (64-bit),
   `[0xca,0xfe,0xba,0xbe]` and `[0xca,0xfe,0xba,0xbf]` (universal). Anything else, a `#!` script
   above all, is `Error::Invalid(text::NOT_NATIVE)`. A file shorter than 4 bytes is `NOT_NATIVE`.
4. Return the canonical path.

### 2.5 The link helper and `sign_in_link`

The helper, byte for byte (a constant; nothing is interpolated into it):

```
#!/bin/bash
umask 077
printf '%s\n' "$1" > "${0%/*}/sign-in-link"
```

`sign_in_link`:
1. Open `<run>/sign-in-link` with `O_RDONLY | O_NOFOLLOW` (`custom_flags`). `NotFound` is
   `Link::NotYet`; any other open error, or a file that is not regular (check the opened file's
   metadata), is `Link::Refused`.
2. Read at most `MAX_LINK + 2` bytes. With no trailing `\n` and at most `MAX_LINK` bytes,
   return `NotYet` and leave the file in place: the helper may still be writing it.
3. Otherwise remove the file (`fs::remove_file`, ignore its error). No trailing `\n`, invalid
   UTF-8, or more than `MAX_LINK` bytes before the newline: `Refused`. Strip the one trailing
   `\n`; `valid_link` false: `Refused`; else `Ready(link)`.

`valid_link(link)` is true only when all hold:
- 1 to `MAX_LINK` bytes;
- every byte is ASCII in `0x21..=0x7e` and none of `" < > \ ^ ` { | }`;
- it starts with `https://claude.com/cai/oauth/authorize?` or `https://claude.ai/oauth/authorize?`
  (the first is what 2.1.292 hands `$BROWSER`; the second is the same page on claude.ai). The
  `?` right after the path is what keeps `https://claude.com.example/…` and `…/authorize@…` out.

## 9. Fixes after the security review (on `9f25552`)

1. **The child must not swap its profile or run folder for a link (HIGH).** `(subpath …)` covers
   the folder itself, so a sandboxed child could `rename` its profile folder away and put a
   symlink to another 0700 folder in its place (measured by the review), and the next
   `Launch::new` canonicalized the link and accepted its target. Two parts, both required:
   - **Profile:** after the `file-write*` allow, add
