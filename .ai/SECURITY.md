# Security: voice

**Last reviewed:** 2026-10-25. The repo is a kit: scripts that read a principal's local history and
write paraphrase, and Persona Builder, the app growing around them. Nothing here runs as a service or
opens a network port. The only network calls are Persona Builder's saving code (`builder/save/`),
which talks to GitHub alone. Reporting: `SECURITY.md`.

## What could go wrong

- A real person's data reaches a commit: a member folder, a name, a quote, a Slack id.
- A principal's raw history is written somewhere other than their state or work folder.
- A crafted export (oversized zip, odd file names, crafted JSON) crashes a miner or escapes its folder.
- A voice recording is committed.
- Someone's assistant is pushed to a public repo, or to a repo nobody confirmed is private.
- A GitHub sign-in token leaks: into a file, a log, a command line or an error message.

## Controls

| Risk | Control | Proven how |
| --- | --- | --- |
| Personal data committed | The repo ships no members; member-specific values come from config outside the repo; `privacy-check` scans a member's tracked files before the build commits | `tests/crew_*_test.py`, build step 11 |
| Raw history leaks | Every write is an O_EXCL, O_NOFOLLOW 0600 file in a 0700 folder outside the repo; miners refuse a work folder inside a git tree | `tests/crew_hardening_test.py`, `tests/slack_mine_test.py` |
| Principal's own words committed | `crew_decisions.py shingle` (no run of 6 of their words) | build step 11 |
| Model-written step files (labels, predictions, round answers) | In Rust (`persona-builder` chunk, check-labels, tally, distil-in, score, similar, shingle, round): every file is `NAME` or `FOLDER/NAME` in the state folder, read and written without following a link, the state folder refused when others can change it and a sub-folder when others can open it; every JSON file checked whole before use (UTF-8, no NaN, only exact numbers); a wrong shape is a plain error or, in check-labels, a reported problem, never a crash; errors name a file, a line, a key or an id. Known limit: a label key or category the model wrote is echoed in an error, as the Python does | `builder/steps/tests/rules.rs`, `builder/ingest/tests/private_at.rs`, `builder/cli/tests/steps_parity.rs` |
| The interview's drafted questions | `persona-builder interview draft` sends no record to the model: the prompt holds only the codebook's areas and kinds of decision (with counts when an earlier build's labels are given), and the argv only fixed text and a fixed schema. The reply is untrusted: checked whole by `round`'s rules plus exactly 20 questions numbered in order, headers from the codebook and length caps, then rebuilt with only the keys `round` reads; errors never repeat the draft's words. A misfit draft is asked for once more; a failed or capped call never. Waiting questions are not replaced without `--replace`. `interview answer` runs the answers through the filters and refuses to overwrite an earlier file with nothing | `builder/build/tests/interview.rs`, `builder/cli/tests/interview.rs` |
| The build's model calls and what they write | `persona-builder build` puts only fixed text in the argv (each step's system prompt names no one and holds no codebook, and each schema is fixed); the codebook, the records, the draft and the precedents go on stdin. The labeller sees held-out questions without their answers, and the backtest sees the draft (written from training records only), each held-out question and its training-split precedents, never the answers. Every reply is untrusted and checked whole before use: labels rebuilt per kind and mode (never a held-out reason) then `check-labels`' rules; distilled sections as structured one-line points within the brief's limits, rendered by the code, none sharing a 6-word run with the corpus or tripping a filter; predictions one per question with exact option labels. A shown error names counts and places, never words. One retry per misfit, none for a failed or capped call. Checked replies are kept 0600 in the state folder's `build/` and re-checked before reuse. A distilled point holding a control character, a line or paragraph separator, a listed invisible character (zero-width, bidi, soft hyphen, BOM, variation selectors, tag characters, fillers) or `<` is refused (no hidden markup, no word split past the checks); only `YYYY-MM-DD` dates the build reads reach the draft (the tally's last-seen date is the steps crate's, unchanged). Before any call the member folder is checked (both files real or absent, no linked `briefs/`), so a refusal there costs nothing; a distil group too big for one call stops before it is sent. The new `decisions.md` and measurements entry pass the filters, are staged beside the member's files (created new, no links followed) and renamed last, so a failed or capped run leaves the member as it was; a staged file a killed run left is swept by the next write (regular files only). Known limits: the two renames are not one atomic step (decisions.md goes first, untested), a large group is refused rather than split, and the lens step's shingle check (documents) is not built | `builder/build/tests/build.rs`, `builder/cli/tests/build.rs` |
| A refresh changing the assistant | `persona-builder refresh` never applies a change without an approval from the right person (`role: subject`, the person themselves, for a person's assistant; `staff` for a product's) on the version it was drafted for. The model answers structured edits, never a diff: the code builds `decisions.md` and the diffs. Every new line, the summary and each reason are checked when drafted and again before applying (one line, no hidden character, the filters, no run of 6 of the person's words from the tests and their answers), and a saved change is read back as untrusted: its diffs apply strictly or not at all. Testing sees each test's situation and options, never the right answer; written answers are graded by a call that sees only the right answer and the answer, under labels that do not say which version wrote it. The result is saved before any member file is written; a kept change replaces `decisions.md` (staged, then renamed), an undone one never writes it. A rerun finishes what is left, re-checking the saved change and the saved result's own tests and regressions (an undone result is also checked by the keep-or-undo rule again), and writes only the version that was tested; the apply hands on the change it checked, never a second read of it. An added line may end in one `\r` only as a `\r\n` line ending, in a part of the change whose last unchanged or removed line ends `\r\n`; a `\r` anywhere else, a `\r` with no `\n` after it, and a hidden character at either end of an added line refuse the change. Known limits: the approval names the change by id, not by a hash of its content, so a hand-edited private record is caught by the re-checks, not by the approval; an edit to `decisions.md` in the moment between the last read and the rename is overwritten, as in the build; the 6-word check covers the tests the change names and their answers, not every test; a rerun does not re-check that a saved kept result covered every test active when it ran (its tests are active by then); in a `\r\n` file, a change that adds a line above the first one, or after a last line with no line ending, is refused rather than allowed | `builder/grow/tests/refresh.rs`, `builder/grow/tests/apply.rs`, `builder/cli/tests/refresh.rs` |
| Secrets in records | Anchored token patterns in the template's and the Slack miner's secret filters drop the record | tests for each shape |
| Crafted exports | Zip size and ratio caps; names flattened; one-line errors instead of tracebacks. In Rust (`persona-builder claudeai`): the export read in memory, never unpacked; links refused; a 2 GB cap on every form; the 100:1 ratio checked before decompressing and the read capped at the declared size; a repeated zip name or inconsistent headers refused; stored and deflate only; errors name places, never words | `tests/crew_hardening_test.py`, `tests/slack_mine_test.py`, `builder/ingest/tests/claudeai_rules.rs` |
| Crafted documents (lens step) | Symlinks never followed; images never opened; a 50 MiB file cap; `.docx` zip size and ratio caps and any `<!DOCTYPE`/`<!ENTITY` refused before parsing; `pdftotext` run with an argument list, no shell, and a timeout; an out dir inside a git tree refused | `tests/crew_documents_test.py` |
| Extra sources (mail, folders, the live log) | Listed only in the gitignored `private.json` (a `sources` key in `member.json` is refused, and `install.sh` refuses one in any kit config); a source without a `consent` date is never read, and `sources mine` (install step 6) deletes the corpus file of a source whose consent was withdrawn or whose entry was removed, before the merge. Mail and the live log are opened with `O_NOFOLLOW` and checked regular on the open descriptor. Mail: the mbox read-only and streamed; a new message starts only at a From_-shaped line (an address and a time of day) whose next line is a header, and any From_-shaped line left inside a message is counted, so a merge is never silent (a body line shaped like a From_ line and followed by a header-like line still splits there, unseen); a 50 MiB cap per message and 256 KiB on its headers; each message parsed under a 10-second timer, and a parse error, a recursion error or the timer is a count, never a stop; only mail from the principal's own addresses and, when labelled, in Sent and not a draft, spam or trash; recipients and subject read only to decide and never stored; quoted lines and the line introducing them, forwards, `-- ` signatures, phone sign-offs and the last common English closing (after some of their words, with at most 300 characters of signature after it, a `PS:` or `P.S.` and what follows it kept) cut, so a longer signature or notice, a second one below a PS, or the first signature of a mail with a second closing below its PS, stays and the filters are its backstop; a host corpus never takes a source's file name (`install.sh` mines a Mac named `live`, `interview`, `claudeai`, `src-…` or `round-…` as `host-…`); the filters per paragraph, then per record; a message's parse errors are a count, never a traceback. Folders: read in place through the lens reader's walk (no links, hidden names skipped), only files marked `y` in a review that the walk also finds (a hand-edited row cannot reach outside the folder); path patterns matched folder by folder with `fnmatch` (no runaway backtracking); files Claude Code wrote or edited (their paths from the transcripts' Write and Edit calls, never the content) and agent files start as `n`; a file name with a tab or line break, or one tripping a filter, is skipped. Live: training only, deduped against the history. Errors name a source and a key, never a path, an address or text (an OS error keeps only its reason). Known limits: a received mail whose unescaped body holds a whole From_ line and headers still splits into a forged message, so the control is the exporter escaping body `From ` lines as `>From` (not checked for Google Takeout); the Rust member loader does not yet refuse `sources` in `member.json` (its port is card PB2.5); `review` on the no-history route reads the paths, never the content, of the adult's Claude Code writes, to mark those files not the principal's; `sources mine` run by hand on that route is kept from mail and the live log by PROMPT.md and `install.sh`, not by the command; the live log is capped at 64 MiB; the timer needs `setitimer` (macOS, Linux); a file an agent wrote through a shell, or Codex wrote, is not caught by the scan (the marks are the backstop); Gmail's label names are taken as Takeout writes them in English; a signature with no `-- ` and no English closing above it stays, so the filters are its backstop; with no transcripts folder `review` says so and nothing starts as Claude's | `tests/crew_extra_sources_test.py`, `tests/crew_install_test.sh` |
| Mining the wrong person | `install.sh --no-history` reads no Claude Code history, no export, no mail and no live log on the Mac it runs on (the adult's, when the principal has no account) | `tests/crew_install_test.sh` |
| A kit weakening filters | `install.sh` refuses kit symlinks and kit-supplied `filters` or `state_dir` | `tests/crew_install_test.sh` |
| An assistant pushed somewhere public | Before every push: the privacy check, over every file the save commits (untracked and ignored files included), then every push address must be a GitHub repo that GitHub's API reads back as `private: true` and `visibility: private`; any other host, a public repo or an unconfirmed one is refused. A new repo is created private and read back before the first push. Saves to a person's own repo go to a `persona/<slug>` branch built from a scratch index, so their index and work tree are never touched, and a save is refused while that branch is checked out anywhere | `builder/save/tests/flow.rs`, `github.rs`, `git.rs`, `verifier_fixes.rs`; `builder/cli/tests/save.rs` |
| The app's screens reaching files or running programs | The webview names no file or folder: a request carries an assistant's slug, checked in Rust to be exactly a slug and, for showing a folder or giving permission, one the listing returns. The capability grants only the app's own commands (no plugin, no `core:` permission), and the command lists are checked against each other. A failure reaches the screens only as a fixed sentence (one repeats the name the person typed), never an error's own text or a path. *Show in Finder* runs `/usr/bin/open -R` (reveal, never open: a linked `.app` folder isn't launched) | `builder/app/tests/lockdown.rs`, `builder/api/tests/assistants.rs` |
| Reading history without permission | Permission is kept per assistant as `consent.json` in its private state folder (0600 in 0700), with the wording's version and the date; it counts only at the current version, with exactly those two keys and a real date, and the wording is pinned by a SHA-1 a test checks. Making an assistant clears any old record for its name. Every app history command first checks the slug against the assistant listing, refuses a state folder outside its private Claude folder, and requires that current agreement in Rust; the native export picker checks it before opening too. Writers hold the private state lock for the whole command | `builder/api/tests/assistants.rs`, `builder/api/tests/history.rs`, `builder/core/src/consent.rs` |
| The app's GitHub sign-in | The device code stays in Rust; the screens get only the code a person types. One sign-in at a time: starting again, cancelling or signing out stops a waiting one, and a stopped sign-in never saves its token (checked under the same lock the save holds). The screens open no web page: Rust opens two fixed GitHub pages by name, never a URL from a request or from GitHub's reply. A save choice names its place and kind in Rust's own list, never a path, and a list that changed answers "look again". A failure shows only a save-crate sentence (`text::is_said`) or a fixed one; git's error line loses any `user:password@` | `builder/api/tests/save.rs`, `builder/save/tests/text.rs`, `git.rs`, `github.rs`; `builder/app/tests/lockdown.rs` |
| The app changing the Claude folder or deleting history | Turning on and off go through the same `install` code as the CLI, with its record, symlink and rollback rules; the app turns one on only when nothing else is on (same slug and same folder count as "this one"), and turns off only the one the person saw (the record's slug must match). The claude.ai files are written only into the assistant's private folder, replaced under the state lock, and only files named like the pack's own are ever listed. Forget deletes only `~/.claude/state/<slug>`, under the state lock, and only when the count the person confirmed equals the count under the lock; the assistant's own folder is never touched. A record's name reaches the screens only after `check_name` | `builder/api/tests/use_it.rs`, `builder/app/tests/lockdown.rs` |
| A GitHub token leaks | The token lives only in the computer's own password store: the macOS Keychain, written through `security -i` on stdin; Windows' Credential Manager (persisted on this computer only, never roaming); or the Secret Service on Linux, over an encrypted session. Where no store runs (a Linux machine with no keyring) sign-in is refused, never kept in a file; a store's error that carries the stored bytes is wiped before it drops; a `Secret` type hides it from `Debug` and zeroes it on drop; HTTP sends it only to `api.github.com` (the request type takes static header values only); git gets it as an environment header scoped to `https://github.com/` for the backup repo only, with the person's git config, helpers and prompts off; git's errors are shown with the token replaced | `builder/save/tests/keychain.rs`, `system_store.rs`, `ureq_wire.rs`, `git.rs`; `builder/keystore/tests/` |
| Audio committed | `.gitignore` blocks audio types and `ref/`, `out/` | `git status --ignored` |
