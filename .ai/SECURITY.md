# Security: voice

**Last reviewed:** 2026-10-25. The repo is a kit: scripts that read a principal's local history and
write paraphrase, and Persona Builder, the app growing around them. Nothing here runs as a service or
opens a network port. The only network calls are Persona Builder's saving code (`builder/save/`),
which talks to GitHub alone. Reporting: `SECURITY.md`.

## What could go wrong

- A real person's data reaches a commit: a member folder, a name, a quote, a Slack id.
- A principal's raw history is written somewhere other than their state or work folder.
- A crafted export (oversized zip, odd file names, crafted JSON) crashes a miner or escapes its folder.
- A voice recording is committed.
- Someone's assistant is pushed to a public repo, or to a repo nobody confirmed is private.
- A GitHub sign-in token leaks: into a file, a log, a command line or an error message.

## Controls

| A copy of the app is swapped or damaged on its way to someone | Against a swap: the build writes the zip's SHA-256, sent in a separate message that says to check it first, and step 3 of `How to install.txt` has the person compare it before running anything from the zip (the installer and the how-to travel in the zip, so neither can vouch for itself). Against damage: the copy is ad-hoc signed and the installer checks the signature (`codesign --verify --deep --strict`) before and after copying. The installer clears the download quarantine only on its own copy in `~/Applications` (the strict check refuses a symlink that leaves the bundle), asks for no password, and refuses a copy for the other chip; the build runs only from a git checkout and refuses uncommitted sources. Known limit: an ad-hoc signature shows a copy is whole, not who made it, so copies go only to people the maintainer knows until it is signed (PB-D3) | `tests/mac_install_test.sh` (damage, chip, quarantine scope, a symlinked app, a symlink out of the bundle); the SHA-256 comparison is the person's own step, untested |

| The build's model calls and what they write | `persona-builder build` puts only fixed text in the argv (each step's system prompt names no one and holds no codebook, and each schema is fixed); the codebook, the records, the draft and the precedents go on stdin. Every reply is untrusted and checked whole before use: labels rebuilt per kind and mode (never a held-out reason) then `check-labels`' rules; distilled sections as structured one-line points within the brief's limits, rendered by the code, none sharing a 6-word run with the corpus or tripping a filter; predictions one per question with exact option labels. Before any call the member folder is checked (both files real or absent, no linked `briefs/`), so a refusal there costs nothing; a distil group too big for one call stops before it is sent. | A refresh changing the assistant | `persona-builder refresh` never applies a change without an approval from the right person (`role: subject`, the person themselves, for a person's assistant; `staff` for a product's) on the version it was drafted for. The model answers structured edits, never a diff: the code builds `decisions.md` and the diffs. Every new line, the summary and each reason are checked when drafted and again before applying (one line, no hidden character, the filters, no run of 6 of the person's words from the tests and their answers), and a saved change is read back as untrusted: its diffs apply strictly or not at all. Testing sees each test's situation and options, never the right answer; written answers are graded by a call that sees only the right answer and the answer, under labels that do not say which version wrote it. The result is saved before any member file is written; a kept change replaces `decisions.md` (staged, then renamed), an undone one never writes it. A rerun finishes what is left, re-checking the saved change and the saved result's own tests and regressions (an undone result is also checked by the keep-or-undo rule again), and writes only the version that was tested; the apply hands on the change it checked, never a second read of it. An added line may end in one `\r` only as a `\r\n` line ending, in a part of the change whose last unchanged or removed line ends `\r\n`; a `\r` anywhere else, a `\r` with no `\n` after it, and a hidden character at either end of an added line refuse the change. Known limits: the approval names the change by id, not by a hash of its content, so a hand-edited private record is caught by the re-checks, not by the approval; an edit to `decisions.md` in the moment between the last read and the rename is overwritten, as in the build; the 6-word check covers the tests the change names and their answers, not every test; a rerun does not re-check that a saved kept result covered every test active when it ran (its tests are active by then); in a `\r\n` file, a change that adds a line above the first one, or after a last line with no line ending, is refused rather than allowed | `builder/grow/tests/refresh.rs`, `builder/grow/tests/apply.rs`, `builder/cli/tests/refresh.rs` |
| Secrets in records | Anchored token patterns in the template's and the Slack miner's secret filters drop the record | tests for each shape |
| Crafted exports | Zip size and ratio caps; names flattened; one-line errors instead of tracebacks. | Extra sources (mail, folders, the live log) | Listed only in the gitignored `private.json` (a `sources` key in `member.json` is refused, and `install.sh` refuses one in any kit config); a source without a `consent` date is never read, and `sources mine` (install step 6) deletes the corpus file of a source whose consent was withdrawn or whose entry was removed, before the merge. Mail and the live log are opened with `O_NOFOLLOW` and checked regular on the open descriptor. Mail: the mbox read-only and streamed; a new message starts only at a From_-shaped line (an address and a time of day) whose next line is a header, and any From_-shaped line left inside a message is counted, so a merge is never silent (a body line shaped like a From_ line and followed by a header-like line still splits there, unseen); a 50 MiB cap per message and 256 KiB on its headers; each message parsed under a 10-second timer, and a parse error, a recursion error or the timer is a count, never a stop; only mail from the principal's own addresses and, when labelled, in Sent and not a draft, spam or trash; recipients and subject read only to decide and never stored; quoted lines and the line introducing them, forwards, `-- ` signatures, phone sign-offs and the last common English closing (after some of their words, with at most 300 characters of signature after it, a `PS:` or `P.S.` and what follows it kept) cut, so a longer signature or notice, a second one below a PS, or the first signature of a mail with a second closing below its PS, stays and the filters are its backstop; a host corpus never takes a source's file name (`install.sh` mines a Mac named `live`, `interview`, `claudeai`, `src-…` or `round-…` as `host-…`); the filters per paragraph, then per record; a message's parse errors are a count, never a traceback. Folders: read in place through the lens reader's walk (no links, hidden names skipped), only files marked `y` in a review that the walk also finds (a hand-edited row cannot reach outside the folder); path patterns matched folder by folder with `fnmatch` (no runaway backtracking); files Claude Code wrote or edited (their paths from the transcripts' Write and Edit calls, never the content) and agent files start as `n`; a file name with a tab or line break, or one tripping a filter, is skipped. Live: training only, deduped against the history. Errors name a source and a key, never a path, an address or text (an OS error keeps only its reason). Known limits: a received mail whose unescaped body holds a whole From_ line and headers still splits into a forged message, so the control is the exporter escaping body `From ` lines as `>From` (not checked for Google Takeout); the Rust member loader does not yet refuse `sources` in `member.json` (its port is card PB2.5); `review` on the no-history route reads the paths, never the content, of the adult's Claude Code writes, to mark those files not the principal's; `sources mine` run by hand on that route is kept from mail and the live log by PROMPT.md and `install.sh`, not by the command; the live log is capped at 64 MiB; the timer needs `setitimer` (macOS, Linux); a file an agent wrote through a shell, or Codex wrote, is not caught by the scan (the marks are the backstop); Gmail's label names are taken as Takeout writes them in English; a signature with no `-- ` and no English closing above it stays, so the filters are its backstop; with no transcripts folder `review` says so and nothing starts as Claude's | `tests/crew_extra_sources_test.py`, `tests/crew_install_test.sh` |

`persona-builder record` writes only into an existing state folder, so it never undoes Forget's
removal. It appends to a regular owner-only file under `flock` and has no `--log`. The SKILL.md's
command is one double-quoted path the app checks for shell characters before writing it. A
release build writes it only from a place that lasts: the canonical path must be under the home
folder or `/Applications`, not under `/Volumes` or an `AppTranslocation` folder, and the command and
every folder above it must be owned by the person or root and not writable by others; anything else
is refused with a sentence that says to install with `install.sh` (`builder/core/src/cli_command.rs`
tests). Known limits: a development build skips the rule (it runs from its own build folder); a
folder writable by its group (as `/Applications` is, for admins) is allowed; the rule is checked
when the assistant is made, not each time the command runs.

The texts an assistant's SKILL.md records or looks up never pass through the
shell: the SKILL.md (and the guided build's backtest brief) gives them to `--stdin` as one JSON
object inside a quoted heredoc, which the shell does not expand and valid JSON cannot end early.
Both programs read at most 64 KiB, strict UTF-8, one object with only the known keys; anything
else is a usage error and nothing is written. `scripts/crew_personas.py similar` (the persona
panel briefs) still takes its query on the command line. Known limit: the protection is Claude
writing valid JSON, with a line break as `\n`. A real line break followed by a line
`END_OF_TEXT` ends the heredoc early and every line after it runs as shell code; the commands
refusing the cut-off JSON does not stop that.
